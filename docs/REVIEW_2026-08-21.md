## 0. 総評

- **品質の土台は高い**。SPI 転送形式、TWR の算術（40bit/32bit の扱い、遅延送信時刻の `>>8`・`&0xFFFFFFFE`、DS-TWR 非対称式、SS-TWR クロックオフセット補正）、PHY 設定、フレーム長、NVS blob の検証順序、コンソールの入力検証は、すべて一次資料・公式サンプルと一致している。
- **しかし「実機で最初に踏む」欠陥が複数残っている**。特に下の 1〜4 は、実機が届いても測位まで辿り着けない類のもので、実機到着前に直しておく価値が高い。
- **ホストテストが通っていることが安全の根拠にならない領域**（スタックサイズ、SPI レート、PRETOC、同一平面検出×アンテナ遅延、低冗長度での外れ値）が、まさに欠陥の出た場所だった。

## 1. `components/uwb_port` / `boards/` / `firmware/probe,devtest`

### H-1. `decamutexon()` = `portENTER_CRITICAL` の内側で SPI（ブロッキング API）と `ESP_LOGE` が走る
- **【対応済み 2026-08-21】** `uwb_port.c` の `decamutexon()` を `s_irq_active ? (gpio_intr_disable(pin_irq), 1) : 0`、`decamutexoff(s)` を `if (s) gpio_intr_enable(pin_irq)` に置換し、`g_deca_mutex` を削除。根拠（SDK の契約、公式 nRF `deca_mutex.c`、ESP-IDF `gpio.c` のコア親和性）は実装コメントに記載。
- `uwb_port.c:73-83`。SDK の呼び出し元: `dw3720_device.c:5443-5473`（`ull_setinterrupt`、レジスタ read-modify-write を 6 回以上）、`:5832-5837`（`ull_forcetrxoff` → `dwt_writefastCMD`）。後者は `stopRadioAndClearRxStatus()` 経由で **受信タイムアウトのたびに通る通常経路**。
- critical section 内で `spi_device_acquire_bus(..., portMAX_DELAY)`（`:131`）→ バスが他デバイスに取られていれば `xSemaphoreTake` でブロック＝割り込み禁止のままコンテキストスイッチ不能。エラー経路の `ESP_LOGE`（`:167, :216`）も stdout ロックを取る。現状は専有バスで「偶然動く」が、`uwb_port.c:119-121` 自身が想定する StampFly HW-2（BMI270 と SPI 共有）で確実に再現する。
- Qorvo の契約は「UWB IC の IRQ 線だけを禁止→復元」（`deca_device_api.h:3233-3253`、公式 nRF 実装は `nrf_drv_gpiote_in_event_disable`）。
- **修正案**: `decamutexon()` を `s_irq_active ? (gpio_intr_disable(pin_irq), 1) : 0`、`decamutexoff(s)` を `if (s) gpio_intr_enable(pin_irq)` に。本ポートの ISR はセマフォ give だけなので no-op でも契約上問題ない。

### H-2. fast レート（16MHz）へ切り替える経路が存在しない（常時 2MHz）
- **【対応済み 2026-08-21】** `uwb_port.h` に `uwb_port_spi_use_fast_rate(bool)` / `uwb_port_spi_active_hz()` を追加。`Qm33120::begin()` 冒頭で slow を明示し、`Qm33120::init()` の `dwt_configure()` 成功直後（IDLE_PLL 確定後。UM Table 4「INIT_RC … limited to 7 MHz」）に fast へ切替。`begin()` 成功ログに `spi: slow=… fast=… active=…` を出す。`uwb_qm33120_types.hpp` の `spi_fast_hz` コメント、`BRINGUP.md`・`GETTING_STARTED.md` の切り分け手順（`firmware/probe` は `begin()` を呼ばないため常に 2MHz）を訂正。
- `uwb_spi_setfastrate()`（`uwb_port.c:242`）は `dwt_spi_s` のコールバックとしてのみ公開。SDK で呼ぶのは `dw3720_device.c:10586, 10607` の非標準 I/F `init()` / `_init_no_chan()` だけで、`dwt_initialise()`（`deca_compat.c:243`）→ `ull_initialise()` は呼ばない。`uwb_qm33120/src/*.cpp`、`firmware/*` にも呼び出し無し（grep 0 件）。
- 食い違う文書・設定: `uwb_qm33120_types.hpp:83`（「dwt_probe()/dwt_initialise() 後に切替」）、`firmware/probe|twr` の `UWB_SPI_FAST_HZ`（切り分け手段として無意味）、`docs/BRINGUP.md:94-95`、`docs/GETTING_STARTED.md:328-333, 424, 1093, 1123`、`docs/TIMING_PRESETS.md:60-63`（折返し 100〜200µs は 16MHz 前提。2MHz だと約 3 倍）。
- TWR への影響: DS タグの Response 受信→Final 予約が約 12 トランザクション・110 byte ≈ 600〜650µs（16MHz なら ≈240µs）。PollingBoth の予算 1658µs に対し最悪 1690µs で余裕ゼロ〜負（§2 H2 参照）。
- **修正案**: `Qm33120::begin()` で `dwt_initialise()`（<7MHz 制約）成功後に `uwb_port_spi()->setfastrate()` を明示的に呼び、起動ログに実効レートを出す。

### M-1. `deca_sleep(n)` の実保証が (n−1) tick。SDK は「DW3720 は 1.5ms 必要」で `deca_sleep(2)` を使う
- `uwb_port.c:63-66` `vTaskDelay(pdMS_TO_TICKS(time_ms))`。SDK: `dw3720_device.c:6110-6114`（softreset 後 1.5ms）、`:6093`、`:4693`。tick 境界直前だと実時間 ~1.0ms。公式 STM は `HAL_Delay`（+1 tick 保証）、nRF は busy-wait。
- 付随: 生成 `sdkconfig` は gitignore 済みなので、古い `sdkconfig`（100Hz）で組むと `pdMS_TO_TICKS(1..9)=0` で無待機になる。
- **修正案**: `vTaskDelay(pdMS_TO_TICKS(ms) + 1)`、または `ms <= 2` は `esp_rom_delay_us`。`CONFIG_FREERTOS_HZ < 1000` を `#error` で弾く。

### M-2. StampFly 構成（`pin_rst` 未配線）ではリセット手段が皆無。`dwt_softreset()`/`dwt_checkidlerc()` を呼ぶ経路が無い
- `boards/stampfly.h:155`、`uwb_port.c:266-271`、`uwb_qm33120.cpp`（grep 0 件）。SDK は `ull_initialise` が「reset/power-up 直後」を前提（`dw3720_device.c:912-916`）。公式 4 サンプルは `reset_DWIC(); Sleep(2); while(!dwt_checkidlerc()); dwt_initialise()`。
- `idf.py flash` / `esp_restart()` / WDT で ESP32 だけ再起動し DW3720 が RX 中や SLEEP のまま残った状態で `begin()` すると不整合。
- **修正案**: `pin_rst == UNUSED` のとき `dwt_probe()` 成功直後に `dwt_softreset(1)`（slow レートで）→ `while(!dwt_checkidlerc())`（タイムアウト付き）。`pin_rst` 有りでも `dwt_checkidlerc()` 待ちは 1 行足す価値あり。

### M-3. RSTn プルアップの文書助言がデータシートと矛盾（コードは正しい）
- `docs/SOLDER_PADS.md:431-442`、`docs/GETTING_STARTED.md:77, 344, 1120`、`docs/BRINGUP.md:90-93` が「10kΩ プルアップ／`GPIO_PULLUP_ONLY` を追加」と推奨。
- `docs/refs/QM33120W_DS.txt:483-485`「RSTn … **Must not be pulled high by the external source.** … driven high by the POR circuit」。外付けプルアップは不要かつ仕様違反。
- **修正案**: 文書から削除し「IC 自身が H に駆動。Hi-Z/オープンドレインで Low に引くだけ」に書き換え。`uwb_port.c:494-496` は `gpio_config` で pull-up/down 両方 disable を明示。

### M-4. `uwb_port_hard_reset()` / `set_wakeup()` / `wakeup_device_with_io()` に `s_initialized` ガードが無い
- `uwb_port.c:266-281, 283-289, 299-307`。`s_cfg` ゼロ初期化のままだと `pin_rst == 0` が UNUSED(-1) 判定をすり抜け、**GPIO0（strapping／AtomS3・StampFly のボタン）を Low に駆動**する。`uwb_port_irq_enable()`（`:352-356`）は同じ罠にガードを入れており不一致。シナリオ: `port_already_initialized=true` で `begin()`（`hard_reset_on_begin` 既定 true → `uwb_qm33120.cpp:580`）。

### M-5. RSTn を push-pull 出力にしてから Low を書く順序
- `uwb_port.c:276-277`。出力ラッチが 1 なら一瞬 H を駆動（DS 違反）。公式 STM は `GPIO_MODE_OUTPUT_OD`。init で OD + level 1（=Hi-Z）に固定し、reset は level 0→待ち→1 だけにする。CS（`:490-492`）も level を先に。

### Low
- **L-1** CS パルスによるウェイクアップで MOSI Low を保証していない（`uwb_port.c:314-327`、UM「SPIMOSI line is held low for the duration of SPICSn」）。AtomS3/StampFly（WAKEUP 未配線）で `dwt_probe()` のたびに通る。ダミー SPI read（全ゼロ送信 ≥500µs）に置き換えれば保証できる。
- **L-2** IRQ 極性は DS で確定できる（`QM33120W_DS.txt:338-342`「By default, IRQ is an active-high output … will float in SLEEP … unless pulled low」）。`GPIO_INTR_POSEDGE` + pull-down は正しい。「極性未検証」を既定無効の理由にするのは弱い。
- **L-3** 「L1 OK / L2 FAIL → RSTn プルアップ追加」（`BRINGUP.md:150`, `GETTING_STARTED.md:427`）は論理的に成立しない。`dwt_probe()` は wakeup パルス + 同じ 1 byte read なので、差が出る要因は wakeup（L-1）か SPI 再現性のみ。
- **L-4** `init_spi_bus=false` で他者のバスを使うと `max_transfer_sz` が 4092 になり、4096 までのチェック（`:151, :189`）を通った転送が `ESP_ERR_INVALID_ARG` になる。現状最大 130B で未到達。
- **L-5** `uwb_port_irq_disable()`（`:423-435`）の `vSemaphoreDelete` は別コア ISR との極小窓。セマフォは削除せず保持でよい。
- **L-6** 文書間の細部: 最小配線本数（6/7/8 本）、AtomS3 layout B（G38/G39）が配線表に無い。

## 2. `components/uwb_qm33120`（TWR 層）/ `firmware/twr`

### C1. 【Critical】DS-TWR は全プリセットで失敗する — `dwt_setpreambledetecttimeout(5)` が RX 窓の開き方と整合しない（R9 の移植ミス）
- **【対応済み 2026-08-21】** `requestDSRange()` / `respondDSRange()` とも `dwt_setpreambledetecttimeout(0)` に戻した。ファイル冒頭の R9 コメントと両呼び出し箇所のコメントを「PRETOC は RX 開放起点。使うなら RX 開放〜プリアンブル先頭までを PAC 単位で計算する」に書き換え。`docs/archive/REIMPL_PLAN.md` R9 を移植ミスとして訂正、`docs/TIMING_PRESETS.md` §2.3 に PRETOC の注記を追加。
- `uwb_qm33120_twr.cpp:531`（requestDSRange: Response 待ちと DWD 待ちに効く）、`:841`（respondDSRange: Final 待ち）。
- 一次資料: SDK `deca_device_api.h:2368-2372`「X ≥ 1 sets a timeout equal to (X+1)*PAC」。UM `DW3000_Family_User_Manual_wayback.txt:8152-8158`「**The preamble detection timeout starts running as soon as the receiver is enabled to hunt for preamble** … abort the reception … set the RXPTO」。`SYS_STATUS_ALL_RX_TO` は RXPTO を含み（`deca_device_api.h:423`）、待ちループ `:594/:686/:893` は `RxTimeout` で即 return。
- 検算（PAC8、(5+1)×8 sym ≈ **49µs**。Poll RMARKER を t=0）:

| 待ち | プリセット | RX 開放 | 相手プリアンブル先頭 | 差 | 判定 |
|---|---|---:|---:|---:|---|
| タグ Response 待ち | PollingBoth | 42+1538 = 1580µs | 3077−138 = 2938µs | 1358µs | **RXPTO** |
| アンカー Final 待ち | PollingBoth | 3127+513 = 3640µs | 4923−138 = 4785µs | 1145µs | **RXPTO** |
| タグ Response 待ち | AnchorIrq/BothIrq | 452µs | 762µs | 310µs | **RXPTO** |
| アンカー Final 待ち | BothIrq | 1156µs | 1463µs | 307µs | **RXPTO** |

- 公式 `ex_05a/05b` が 5 PAC で動くのは、RX 開放（`POLL_TX_TO_RESP_RX_DLY_UUS`）と応答（`POLL_RX_TO_RESP_TX_DLY_UUS=900`）が「RX 開放の数µs後にプリアンブルが来る」よう調律されているから。本実装は RX を 0.3〜1.4ms 早く開ける設計なので 5 PAC をそのまま移植すると成立しない。`docs/TIMING_PRESETS.md §2.3` の「✅」表はフレーム待ちタイムアウトだけ計算しており PRETOC を考慮していない。
- 現象: DS-TWR を選ぶとタグは毎回 `RX_TIMEOUT`。アンカーは Final 待ちで RXPTO → `RxTimeout` → `anchor main.cpp:467-470` が「Poll 未着」扱いで黙って捨てるためログも出ない。
- **修正案**: 両方 `0` に戻す（M5Stack 原本も 0）。PRETOC を使うなら「RX 開放から相手プリアンブル先頭までの時間 + マージン」を PAC 単位で計算して設定（PollingBoth タグ Response 待ちなら ≈180 PAC）。
- 既定ビルド（SS-TWR）は `dwt_setpreambledetecttimeout(0)` なので影響なし。**実機初回は SS-TWR から始めるのが合理的**。

### H1. SPI 常時 2MHz（§1 H-2 と同一。TWR 側の影響）
- **【対応済み 2026-08-21】** §1 H-2 の修正で解消（`dwt_configure()` 成功後に 16MHz）。
- 折返し時間の見積り `docs/TIMING_PRESETS.md:60-63`（100〜200µs）は 16MHz 前提。2MHz では約 3 倍。

### H2. IRQ プリセットの DS `finalTxDelayUus` に余裕が無い
- `uwb_qm33120_timing.hpp:111`（AnchorIrq 1365）、`:118`（BothIrq 683）。
- AnchorIrq（タグはポーリング）: 予算 1400−50−138 = 1212µs。ポーリング遅延が 0〜1000µs 一様として、16MHz で約 5%、2MHz（現状）で約 45% が `dwt_starttx` late → `TxStartFailed`。BothIrq: 予算 512µs、2MHz では常時失敗。
- **修正案**: H1 を直した上で AnchorIrq の finalTxDelay を 1600〜1700 UUS 程度へ。`dwt_starttx` 失敗回数を統計に出し R5 の方針どおり実測で詰める。`kTimingPresetVersion` を上げる。

### M1. 折返しの最中に `ESP_LOGW`（数百 byte の日本語）を出す
- `uwb_qm33120_twr.cpp:166-186`（`checkTimingTagAndWarn`）。呼び出し `:415`（SS アンカー: Response 予約前）、`:586`（DS タグ: Final 予約前）、`:782`（DS アンカー: Response 予約前）。115200bps で 250〜300B ≈ 22〜26ms ブロック → その交換は `TxStartFailed`。`warned_count==8` 以後の新規ピアは記録されず（`:189`）毎回失敗。
- **修正案**: 警告はフラグで返し、送信予約の後（または main 側）で出す。

### M2. アンカーの Poll 待ちが `hostTimeoutMs`（10ms）ごとに受信機を落とす
- `:384, :493`（満了→`stopRadioAndClearRxStatus()`→return）、`anchor main.cpp:392-397` が即再呼出し。デッドタイム ≈380µs/10ms ≈ 3.8%（16MHz で 2.6%）の Poll 取りこぼし。公式 `ex_06b` はタイムアウト無しで待つ。
- **修正案**: Poll 待ちはホストタイムアウトを長く（≥200ms）、または満了時に `forcetrxoff` せず RX 継続で return。

### Low
- **L1** `resultRxAfterFinalTxDelayUus=200`（PollingBoth, `timing.hpp:128`）は速いアンカーに対し境界的。0 でよい。

## 4. `components/uwb_survey` / `uwb_loc` / `firmware/soltest`

> **【2026-08-21 夕方 対応状況】** `uwb_survey` を `uwb_math` ベースに書き換えた際に **A-1・A-3（result に `redundancy`/`delay_suspect`）・A-5（`n_heights`/`frame_determined`）・A-6（球面拘束の厳密解）・A-7（比 1e-5）・A-8（片方向 NaN）・A-9（eps スケーリング）を対応済み**。A-2 と A-4 は未対応。MDS は逐次三辺測量に、`uwb_survey_dense.c` は削除。詳細は `docs/MATH_AUDIT_2026-08-21.md` の実施状況。

### A-1. 【High】同一平面検出がアンテナ遅延 δ で無効化される
- `uwb_survey.c:256-284`。r = d + 2δ なので r² = d² + 4δd + 4δ²。二重中心化すると B′ = B + 2δ²J − 2δ·JDJ。距離行列は条件付き負定値なので −JDJ ⪰ 0 → **本来 0 の第 3 固有値以降に O(δ·L) の正成分が乗る**。
- 実測（6 台・完全同一平面）: δ=0 → degenerate=1、δ=0.02 → eig2/eig0=4e-3, **degenerate=0**、δ=0.15 → **0**。同一平面 + δ=0.15 + 5cm ノイズ 200 試行 → **ok=1 が 200/200、最大座標誤差 1.52m**（z が勝手に裏返る）。テストは δ=0 でしか縮退を見ていない。
- **修正案**: LM 収束後の最終形状（δ 除去済み）を PCA して縮退判定をやり直す（`fit_up` 直前に最小固有値の rms < 0.05m で `degenerate=1`）。

### A-2. 【High】外れ値リンク棄却が公称 6 台構成で効かない（マスキング）
- `uwb_survey.c:565-608`（`drop_worst_link`）。残差 MAD は外れ値込みの最小二乗後なので、冗長度が低いと外れ値が解に吸収される。n=6・(2,5) に +2.0m → 残差 −0.164、threshold 0.300 → 落とさない。結果 `ok=1, excluded=0, rms=0.091, δ=−0.070（真値 +0.10）, 最大誤差 1.33m`。テストは n=8・無雑音・+側のみ。
- **修正案**: leave-one-out（各リンクを外して LM し直し、コスト減が突出したものを落とす。最大 28 回で十分速い）か Huber-IRLS。δ の妥当範囲チェック（§5「±1m 外なら警告」未実装）。

### A-3. 【Medium-High】冗長度 0 + 欠測で系統的に別解へ落ち、API が冗長度も δ 異常も返さない
- n=6・2 本欠けの全 105 パターン（無雑音）→ **50 パターンで誤解**（誤差 >0.5m、残差 ~1e-16）。5cm ノイズ 500 試行 → 500/500 誤。n=5 全リンクは 0 件。誤解の δ は −0.545m と物理的にあり得ないが検査がない。`uwb_survey_result`（`uwb_survey.h:128-142`）に冗長度が無く仕様 (E) を呼び出し側が実装できない。

### A-4. 【Medium】キラリティ規約が対称配置でコイントス
- `uwb_survey.c:804-818`。ノード 2/3 を y=±4.0 に置き 5cm ノイズ 200 試行 → **y 正 98 / 負 102**。「ノード 0,1 を長方形の対角に置く」と普通に起きる。仕様 §2[4] の `survey chirality cw|ccw` はソルバ入力に無い。
