# アンカー自動測量 仕様 (2026-08-20)

## 目的
**アンカーを適当に設置したあと、巻尺での実測を「各アンカーの高さ5個」だけに減らし、
残りは自動で決めてタグの測位を開始できるようにする。**

## 確定した設計判断
| # | 決定 | 理由 |
|---|---|---|
| 1 | **ゲージ固定は Lv2（高さのみ実測）** | 垂直距離は巻尺で最も正確に測れる。5個で済む |
| 2 | **測量時はタグも6台目として参加** | 距離が 10→15本 に増え、共通アンテナ遅延の推定に余裕ができる |
| 3 | **計算は実機（ESP32-S3）上で行う** | PC 不要。現場完結 |
| 4 | 台間通信は **ESP-NOW** | AP/ルータ不要。2.4GHz なので UWB ch9 と電波干渉しない |
| 5 | 測量モードと運用モードは**排他** | WiFi スタックのジッタが遅延送信のウィンドウを乱すため |
| 6 | **高さも ToF 距離センサで自動計測（オプション）** | 巻尺を完全に不要にする。AtomS3 の I2C に相乗りで増設できる |

## 1. 推定するもの と 自由度

### 観測
6ノード（アンカー5 + タグ1）の総当たり相互測距 = **15本**
```
r_ij = d_ij + δ_i + δ_j     (i<j)
```

### 未知数
- 座標: 6ノード × 3 = **18**
- **共通アンテナ遅延 δ**（全ノード同一と仮定）: **1**
  → `r_ij = d_ij + 2δ`

台ごとに個別推定すると N=6 で 18+6=24 未知数 vs 15式で不足する。
同一製品・同一基板なので共通値とする。APS014 も
「30cm 以下の精度で良ければ台ごとの校正は不要」としている。

### 自由度の勘定（3D）
| 項目 | 数 |
|---|---|
| 観測（距離） | 15 |
| 座標の自由度 | 18 |
| ゲージ（並進3 + 回転3。鏡像は離散） | −6 |
| **実質の形状自由度** | **12** |
| 共通遅延 | +1 |
| **未知数計** | **13** |
| **冗長度** | **15 − 13 = 2** |

タグを入れないと 10本 vs 10未知数で余裕ゼロになる（これが判断2の根拠）。

### 【追記 2026-08-20】実装で判明した制約

**(D) n=4 では共通遅延を推定できない。**
δ の識別可能性は `m >= 3n-6+1`。n=4 は最大6本 vs 必要7本で常に不足する。
実装は自動検出して **δ=0 に固定**する。

**(E) 冗長度0の構成は「残差0の別解」に落ちうる。【重要】**
6ノード2本欠け（13本 vs 未知数13）で、**残差RMS 5.4e-16 のまま
座標2.74m違い・δ=−0.545（真値+0.08）** という解が実際に出た。
データを完璧に説明しているので**残差では検知できない**。

→ **冗長度 `リンク本数 − 未知数 + 6` を利用者に必ず表示し、0以下なら警告する。**
　 §5 の「残差RMSを見て採否を委ねる」ではこの失敗様式を捕まえられない。

**(F) 行列サイズは 25×25。**
`UWB_MAX_ANCHORS=8` に合わせると未知数は 3×8+1 = 25。
本文中の「19×19」は n=6 の場合の値。

## 2. 処理の流れ

```
[1] EDM 収集       ESP-NOW が指揮し、15本の相互測距を集める
[2] 初期配置       古典的 MDS（二重中心化 → 固有分解 → 上位3固有ベクトル）
[3] 精密化         Gauss-Newton で距離残差を最小化。共通遅延 δ も同時に推定
[4] ゲージ固定     実測した高さに合わせて 回転(傾き2) + z並進 + 鏡像 を決定
[5] XY 規約        アンカー0 を XY 原点、アンカー1 が +X 方向
[6] 配信・保存     ESP-NOW で全台に配り、各自 NVS へ保存
```

### [2] MDS の詳細
- 距離行列 D（6×6、`D[i][j] = r_ij − 2δ̂`。δ̂ は初期値0）から
  二重中心化で Gram 行列 B を作る: `B = -0.5 * J D² J`, `J = I - (1/n)11ᵀ`
- **B を固有分解**する。
  **【訂正 2026-08-20】** 当初「上流の最適化 C-1 で固有ベクトル対応済みの
  `uwb_sym_eig()` が使える」と書いたが**誤り**。固有ベクトル対応版は
  `kouhei1970/uwb_localizer` の**未マージブランチ** `perf/exploit-structure` にあるだけで、
  本リポジトリの `components/uwb_loc/` にあるのは固有値のみの `uwb_sym_eigvals()`。
  `uwb_loc` は変更禁止なので、**固有ベクトル付き Jacobi を `uwb_survey_dense.c` に自前で持つ**。
  （上流がマージされ再 vendoring したら、そちらに寄せることを検討する）
- 上位3固有値の平方根 × 対応する固有ベクトル = 初期座標
- **6×6 なので `UWB_LA_MAX=9` に収まる**

### [3] Gauss-Newton の詳細
- 残差: `f_ij = |p_i − p_j| + 2δ − r_ij`（15本）
- 未知数ベクトル: `[p_0..p_5 (18), δ (1)]` = **19**
- ヤコビアン 15×19、正規方程式 19×19
- **`uwb_linalg` は 9×9 が上限なので、測量専用の密行列ソルバを別途持つ**
  （設置時に1回だけ走る処理なので速度要件は緩い。メモリは 19² × 8B ≈ 3KB）
- ゲージの不定性は正規方程式を特異にするので、**Levenberg-Marquardt 的な
  リッジ正則化**を入れるか、ゲージを固定する拘束を追加する

### [3.5] 高さの自動計測（オプション）

**AtomS3 に I2C の ToF 距離センサを付けると、高さ実測も不要になる。**

#### GPIO の空き（ユーザ確認済み）
| 場所 | ピン | 用途 |
|---|---|---|
| 底面ヘッダ | G5 / G6 / G7 / G8 | SPI（MISO/MOSI/SCK/CS） |
| **底面ヘッダ** | **G38 / G39** | **I2C（オンボード MPU6886 と共用）← ToF はここ** |
| Grove ポート | G1 / G2 | RST / IRQ |

I2C はバスなのでアドレスが衝突しなければ増設できる
（MPU6886 = 0x68、VL53L1X 系 = 0x29）。
**SPI / RST / IRQ を一切削らずに済む。**
IRQ はアンカー側の折り返し時間（R5/R6）に効くので、これを失わないのは重要。

#### センサ選定
| 候補 | 上限 | 判断 |
|---|---|---|
| Unit ToF (VL53L0X) | 2m | **天井付近から床を測ると足りない可能性** |
| **Unit ToF4M (VL53L1X)** | **4m** | **推奨。** 天井高 2.4〜3m に余裕を持って対応 |
| VL53L3CX | 3m | `stampfly_ecosystem` に `sf_hal_vl53l3cx` の実装あり（流用候補） |

#### 仕様
- ToF は**真下を向けて床までの距離**を測る。それがそのアンカーの高さになる
- **センサと UWB アンテナの取り付けオフセット**を設定で持つ（既定 0）。
  `h = tof_distance + mount_offset`
- **全台に付けなくてよい。** 3台以上あれば傾きと z オフセットは決まる。
  センサ値と手入力の**混在を許す**
- **測距のばらつきを見て怪しければ警告**する。真下に家具があると誤る
- Kconfig でオプション扱い。無効時は現行通り手入力のみ
- 精度は数cm級（巻尺の1cmより粗い）。ゲージ固定（傾き・z オフセット）には十分

#### 手順への影響
```
survey height auto          ToF 搭載台の高さを一括取得
survey height <addr> <m>    センサ非搭載台のみ手入力
```
**全台に ToF を付ければ巻尺が完全に不要になる。**

### [4] 高さによるゲージ固定

実測した各アンカーの高さ `h_k`（床からの垂直距離）を使う。

**【重要な訂正 2026-08-20】高さでは鏡像は決まらない。**

当初「反転あり/なしの両方を試し、高さ残差が小さい方を採用」と書いたが、
**これは原理的に不可能**である。証明:

```
高さモデル   h_i = u·p_i + c        (u は上方向の単位ベクトル、c はオフセット)
反転 S       直交かつ det(S) = -1
反転後に u' = Su と取ると
    u'·(S p_i) = (Su)ᵀ(S p_i) = uᵀ SᵀS p_i = uᵀ p_i        (SᵀS = I)
```
**反転前後で実現できる高さの組は完全に一致する。**
高さは線形汎関数なので、キラリティ（掌性）を検出できない。

→ 実装は両方を計算して比較するが（診断のため）、**必ず引き分けになる**。
   引き分け時は規約（XY 正規化後、|y| 最大ノードの y を正にする）で一意化し、
   `mirror_resolved = 0` を返す。

#### 鏡像の解決には外部から1ビットの情報が要る
**採用: キラリティを直接問う。**
```
survey chirality cw|ccw
  「上から見下ろして、ノード0 → 1 → 2 が時計回りか反時計回りか」
```
設置した本人なら記憶で答えられる。高さの実測より簡単。
未指定なら鏡像不定のまま返し、**その旨を明示**する
（相対的な位置関係は正しいので、用途によってはそのまま使える）。

#### 高さで決まるもの（訂正後）
- **傾き（回転2自由度）と z 並進**: 推定 z を `h_k` に最小二乗で合わせる
- **【訂正】高さの実測は4点以上必要。** 3点だと中心化後に2次元しか張らず、
  上方向 u の「3点平面の法線成分」は**大きさだけ決まり符号が決まらない**。
  しかも符号によって未実測ノードの z が変わるため、XY 規約では一致させられない。
  実測が3点以下なら形状のみ返し、傾きは未確定として扱う

### [5] XY の規約
- アンカー0 の XY を原点
- アンカー1 が +X 軸上（y=0, x>0）
- **任意だが再現性のある座標系**。飛行制御には支障ない

## 3. ESP-NOW プロトコル

### 役割
- **コーディネータ**: 測量を指揮する1台。タグが兼ねる（PC に挿さっている想定）
- **参加ノード**: アンカー5台 + タグ自身

### フレーム（ブロードキャスト）
| 種別 | 向き | 内容 |
|---|---|---|
| `SURVEY_HELLO` | coord → all | 測量開始。参加ノードは自分の ID を返す |
| `SURVEY_HELLO_ACK` | node → coord | 自分の short_addr |
| `SURVEY_ASSIGN` | coord → all | 「次のイニシエータは addr=X、相手は addr=Y」 |
| `SURVEY_RESULT` | node → coord | 測距結果（addr ペア、距離 mm、成否、試行回数） |
| `SURVEY_DONE` | coord → all | 収集完了。測量モード終了 |
| `CONFIG_PUSH` | coord → all | 確定した座標テーブルと遅延を配信 |
| `CONFIG_ACK` | node → coord | NVS 保存完了 |

- **1リンクずつ順に指名する**（同時に複数が送信すると UWB が衝突する）
- 各リンクは**複数回測って中央値**を採る（回数は設定可能、既定5回）
- 失敗したリンクは `SURVEY_RESULT` で成否を返し、コーディネータが再試行

### 排他制御
- `survey start` で ESP-NOW を初期化、**測位ループは停止**
- `survey stop` / `SURVEY_DONE` で **ESP-NOW を deinit**（`esp_now_deinit` + `esp_wifi_stop`）してから運用モードへ
- **測量中は測位しない。運用中は ESP-NOW を上げない**

## 4. コンソールコマンド（追加分）

**コーディネータ（タグ）**
```
survey start                 測量モードへ。ESP-NOW 起動、参加ノードを集める
survey status                収集済みリンク数 / 未取得のペア
survey height <addr> <m>     アンカーの実測高さを入力（5台分）
survey solve                 MDS + GN + ゲージ固定を実行して結果を表示
survey push                  確定した座標と遅延を全台へ配信し NVS 保存
survey stop                  ESP-NOW を落として運用モードへ
survey abort                 破棄
```

**アンカー**
```
（測量は ESP-NOW 経由で自動。手動介入は不要）
survey info                  自分が参加した測距の成否
```

## 5. 異常系

| 事象 | 扱い |
|---|---|
| 参加ノードが6台に満たない | `survey status` で不足を表示。**5台でも解けるが冗長度0になる**旨を警告 |
| 一部のリンクが取れない（遮蔽） | 再試行。それでも駄目なら**そのリンクを欠測として GN で扱う**（MDS の初期値は残りから作る） |
| MDS の固有値が退化 | 配置が縮退している。エラーを返し、配置を変えるよう促す |
| GN が収束しない | 反復上限で打ち切り、残差 RMS を表示して採否を利用者に委ねる |
| **冗長度が0以下** | **残差が0でも誤った解の可能性がある。必ず警告する**（上記 (E)） |
| 高さ入力が4点未満 | 傾きが決まらない。**形状のみ返し**、その旨を明示（3点でも足りない。上記[4]） |
| キラリティ未指定 | **鏡像が不定のまま返す。** 相対的な位置関係は正しい |
| 推定遅延が異常値 | 妥当範囲（例 ±1m）外なら警告。配線・配置の誤りを疑う |

## 6. 成果物の受け渡し

測量結果は既存の `uwb::AnchorEntry` テーブルにそのまま入る:
```cpp
struct AnchorEntry {
    uint16_t short_addr;
    float    pos[3];            // ← 測量結果
    float    antenna_delay_m;   // ← 推定した共通遅延（全台同値）
    bool     enabled;
};
```
`components/uwb_cfgstore/` の NVS 保存と ESP-NOW 配信を通す。
**既にコンソールで手入力できる形になっているので、受け皿は完成している。**

## 7. 実装の分割

| # | 対象 | 内容 | 実機必要性 |
|---|---|---|---|
| S1 | `components/uwb_survey/` | MDS + GN + ゲージ固定。**ESP-IDF 非依存の純計算**にしてホスト検証可能に | 不要 |
| S2 | 同上 | 測量専用の密行列ソルバ（19×19） | 不要 |
| S3 | `components/uwb_espnow/` | ESP-NOW の薄い層。フレーム定義と送受信 | 実機で要確認 |
| S4 | `firmware/anchor` | イニシエータに回る測量モード | 実機で要確認 |
| S5 | `firmware/tag` | コーディネータ + コンソールコマンド | 実機で要確認 |
| S7 | `components/uwb_tof/` | I2C ToF（VL53L1X）ドライバ + 高さ取得。**オプション** | 実機で要確認 |
| S6 | `tools/test_survey/` | **合成データでの検証**（既知配置 → 距離生成 → 復元 → 誤差評価） | 不要 |

**S1/S2/S6 は実機なしで完結する。** 先にそこを固めてから S3-S5 に進む。

### S6 で検証すること
- 既知配置（非同一平面、5台+タグ）から理論距離を作り、復元誤差が数値誤差レベルであること
- 距離にノイズ（σ=5cm）を乗せたときの復元誤差
- **共通遅延を仕込んで、正しく推定されること**
- 欠測リンクがあるときの挙動
- 縮退配置（同一平面、直線状）で正しくエラーになること
- 鏡像の選択が高さ実測で正しく決まること
