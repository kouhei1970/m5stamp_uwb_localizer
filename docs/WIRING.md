# 配線

**接続経路は3通り。まず §1 で経路を決める。**
配線前に必ず **§5（全経路共通の禁止事項）**（5V 禁止・向きの確認・アンテナ禁止領域など）に目を通すこと。

## 1. どの経路か（最初にここ）

**据置機（アンカー5台 + 据置タグ）は経路A、StampFly 搭載タグは経路C を使う。**
経路B は「変換基板が手元に無い」「FPC コネクタ未実装の S017 しか無い」場合の代替。

| | **経路A: FPC→DIP 変換基板** | 経路B: 半田パッド直付け | **経路C: StampS3A 背面 12P FPC** |
|---|---|---|---|
| 対象 | **据置機（標準構成）** | 代替 | **StampFly 搭載タグ** |
| モジュール | **S017-F**（FPC コネクタ実装済み） | S017 / S017-F 両方 | S017（背面が平らで貼りやすい） |
| ホスト | M5StampS3A + StampS3 BreakOut | 何でも | StampFly の M5StampS3A |
| モジュール側の半田付け | **不要** | **1.27mm パッドへ直付け（最難関）** | 専用基板へ貼付 |
| ホスト側の半田付け | BreakOut に 2.54mm ヘッダ | 不要 | **0.5mm 12P コネクタを背面へ後付け** |
| 着脱 | 可 | 不可（付け外しは半田ごて） | 可 |
| 取れる信号 | 全部（SPI4 + RST + IRQ + WAKEUP） | 配線本数しだい | 全部 |
| 手順 | **§2** | §3 | **§4** |

**経路A と経路B でモジュール側の 12 本の信号は同じ**（§7.1）。違うのは
「FPC コネクタで抜き差しするか、パッドへ直接半田付けするか」だけである。
**ただし番号の並びは違う**ので、§7.1 の対応表で必ず読み替えること。

## 2. 経路A: FPC → DIP 変換基板（据置機の標準）

**モジュール側の半田付けが要らないのがこの経路の要点。** 1.27mm・隣接
0.67mm のパッドへ AWG30 を直付けする §3 の作業が丸ごと不要になる。

### 2.1 用意するもの

| 品目 | 仕様 | 備考 |
|---|---|---|
| **M5Stamp UWB Module with FPC** (`S017-F`) | FPC コネクタ実装済み | **0.5mm 12P FPC ケーブルが標準付属** |
| **0.5mm 12P FPC→DIP 変換基板** | 0.5mm ピッチ・12 ピン | **接点面（同面／異面）を要確認**。下記 |
| M5StampS3A + **StampS3 BreakOut** | — | BreakOut に 2.54mm ピンヘッダを半田付けする |
| ジャンパ線 | **10cm 以内** | 下記の信号品質を参照 |
| **テスター（導通）** | — | **向きの確定に必須。無しで進めない** |

### 2.2 【最重要】向きを確定する

半田パッドの向き確認（§3.2・`GETTING_STARTED.md` §3.1）に相当する手順。
**3V3 を繋ぐ前に必ずやること。** FPC ケーブルには**同面接点と異面接点**が
あり、変換基板側コネクタの接点位置と噛み合わないと、接触しないか
**1 番と 12 番が入れ替わる**。反転すると FPC 1/2（3V3）が FPC 11/12
（GND・CLK）の位置に来るので、**半田付けのときと同じ「電源が信号線に入る」
事故が起きる**。公式も "Do not reverse-insert, otherwise it will damage the
device." と明記している。

幸い FPC 側には**非対称性**がある（§7.1）:
**1・2 番が VCC_3V3（隣接した同一ネット）、7・11 番が GND（4 本離れた同一ネット）。**
パッド側（GND ×3、VCC ×1）とは本数も並びも違う。これを使って一意に決まる。

1. FPC ケーブルをモジュールと変換基板の両方に挿す。**ホスト側にはまだ何も繋がない。**
2. 変換基板の DIP ピン間で導通を測り、**隣り合う 2 本が導通する組**を探す。
   1 組しか無い。それが FPC 1・2 = **VCC_3V3**。
3. その組を 1・2 番として反対端へ数え、**7 番と 11 番が導通する**ことを確認する。
   これが GND。
4. 2 と 3 が同時に成り立つ並びは 1 通りしか無い。逆順で成立したらケーブルを
   裏返すか、挿し方を変える。
5. VCC 側と GND 側が **0Ω で張り付いていない**ことを確認する
   （モジュール内のコンデンサ 24 個で、抵抗レンジでは低い値から徐々に上がる）。
6. ここまで確認してから 3V3 を繋ぐ。

### 2.4 16MHz で走らせるための注意

**この経路は FPC ケーブル + 変換基板 + ジャンパを挟む。** §3.4 が
「ブレッドボードを挟むな」と書いているのと緊張関係にあるので、次を守る。

- ジャンパは **10cm 以内**。できるだけ同じ長さに揃える
- **FPC の GND 2 本（7・11）を両方繋ぐ**（戻り電流経路。片方だけにしない）
- CLK 線に GND を添わせる
- **ブレッドボードではなく短い直結**を推奨
- **FPC ケーブルをモジュールの PCB アンテナの下に通さない**（公式の注意。
  §5.2 のアンテナ禁止領域と同じ理由で、測距距離に直接効く）
- 16MHz で不安定なら `boards/stamps3.h` の `spi_fast_hz` を
  **16MHz → 8MHz → 4MHz** と落として切り分ける（`spi_slow_hz` は変えない）。
  **`firmware/probe` は `begin()` を呼ばないため常に `spi_slow_hz`(2MHz) のまま**
  なので、この切り分けは `firmware/twr` 以降で行う

## 3. 経路B: 半田パッドに直付け（代替）

**モジュール側のパッドへ電線を直付けする。** 1.27mm・隣接 0.67mm の
パッドへの半田付けが最難関の工程になる。

### 3.1 用意するもの

| 品目 | 仕様 | 備考 |
|---|---|---|
| モジュール | S017 / S017-F 両方使える | |
| 電線 | **AWG30 のラッピングワイヤ**（芯線 0.25mm / 外径 約0.5mm）か、**0.2〜0.26mm のポリウレタン被覆線（UEW / エナメル線）** | ピッチ 1.27mm しかないので、デュポン線（AWG24〜26）の直付けは無理がある |
| こて・フラックス | こて先 1.6mm C 型以下、320〜340℃（鉛フリーなら 350℃程度） | 手順は §3.4 |
| **テスター（導通）** | — | **向きの確定に必須。無しで進めない** |
| 固定剤 | エポキシまたは UV レジン | 線の根元固定用（§3.4） |

- UEW を使う場合は、被覆が熱で溶けるタイプ（1UEW/2UEW）でも、**予備はんだ時にきちんと被覆が飛んだか目視確認**する。
- **配線長は 10cm 以内**を目安に。SPI 16MHz を通すので長いほど不利。すべての線をできるだけ同じ長さで揃え、**GND 線を SPI 線と束ねる**。
- **途中でブレッドボードを挟まない。** ブレッドボードの接触抵抗と容量は 16MHz に効く。

### 3.2 【最重要】向きを確定する

1. **面取りの大きい角を探して pin 1 を特定**する。
   モジュール裏面のシルクにピン番号が印刷されている可能性が高いが、**未確認**。
   シルクが無ければ §7.2 の図で向きを決める。
2. **テスターで導通確認**して仮説を検証する。
   - **GND 同士（pin 1 / 8 / 12）の 3 本が互いに 0Ω で導通するか。**
     これが向きの判定に効く。左右反転していれば pin 8 のつもりの所が
     pin 5 (GP7) になり、180° 回転していれば pin 7/2/6 になるので、
     **どちらの誤りもこの 1 つの試験で弾ける**。
   - pin 2（3V3）と GND がベタ短絡（0Ω）していないこと。
     モジュール内にコンデンサが 24 個あるので、抵抗レンジでは
     充電のため最初は低く出て徐々に上がる。**0Ω に張り付かなければ正常。**
   - この 2 点が合えば向きの解釈は正しい。
3. 配線 → 電源投入 → `firmware/probe` で `0xDECA0314` を読む（`GETTING_STARTED.md`）。

### 3.3 配線表（パッド番号 ↔ ホスト）

ホスト側ピン番号は `boards/stamps3.h` / `boards/atoms3.h` と一致させてある。

**`boards/stamps3.h` の SPI 4 本（SCK=G12 / MOSI=G11 / MISO=G13 / CS=G10）は
2026-08-27 に実機で確認済み**（M5StampS3A + StampS3 BreakOut + FPC、1 台。値を
変えずに `firmware/probe` が PASS。→ [`GETTING_STARTED.md` §4.2.1](GETTING_STARTED.md#probe-result)）。
**同じファイルでも RST=G6 / IRQ=G7 / WAKEUP=G8 は未確認**で、`boards/atoms3.h` は
全ピン未確認。**確認済みの 4 本以外は実配線前に現物と照合すること**
（両ファイルの冒頭コメント参照）。

**M5StampS3A（標準構成。BreakOut の有無によらず同じ）**

> AtomS3 は空き GPIO が少ないため WAKEUP/GP7 は未配線。
> `components/uwb_port` は `UWB_PORT_PIN_UNUSED` を扱えるので追加対応は不要
> （`boards/atoms3.h` のコメント参照）。

**配線しないパッドの扱い（`boards/*.h` の設定）**

半田付けは本数を減らすほど楽なので、最初は **7〜10本**で始めるのがよい。
そのとき **`boards/*.h` 側も実配線に合わせる**こと。

| 配線しないもの | `boards/*.h` の扱い | 理由 |
|---|---|---|
| pin 5 (GP7) | **`.pin_gp7 = UWB_PORT_PIN_UNUSED` にする** | 未配線のまま GPIO 番号を入れておくと入力が浮く。<br>現状 `uwb_port_read_gp7()` を呼ぶファームは無いので実害は出ていないが、<br>合わせておくのが安全 |
| pin 3 (WAKEUP) | `UWB_PORT_PIN_UNUSED` にしてよい | ホスト側は出力なので浮いても害はない。<br>未設定時は CS パルスによるウェイクにフォールバックする<br>（`uwb_port_wakeup_device_with_io()`） |
| pin 4 (IRQ) | `UWB_PORT_PIN_UNUSED` にしてよい | ドライバはポーリング方式。ホスト側は入力なので、<br>番号を残したまま未配線にすると浮く |
| pin 6 (RSTn) | **配線を強く推奨** | `uwb_port_hard_reset()` が使えなくなる。<br>`UWB_PORT_PIN_UNUSED` の場合は待つだけになる |

**Phase 1（`firmware/probe` で `0xDECA0314` を読むだけ）なら
pin 2 / 7 / 8 / 9 / 10 / 11 / 12 の 7 本 + pin 6 (RSTn) の計 8 本で十分。**

### 3.4 半田付けの手順

**手順**

1. モジュールを両面テープでまな板（適当な板／耐熱マット）に固定する。
   **アンテナ側（面取りのある端）3.5mm には金属を置かない。**
2. 使うパッドにだけ**フラックスを塗って予備はんだ**を薄く盛る。
   隣接パッドとの隙間は 0.67mm しかないので、盛りすぎない。
3. 線の先端 1mm を予備はんだし、切り欠きに当てて **こて先 1 秒**で付ける。
   こて先は **1.6mm C 型以下**、温度 320〜340℃、鉛フリーなら 350℃程度。
4. 全部付けたら **拡大鏡で隣接ブリッジを確認** → **テスターで隣接ピン間の
   導通が無いことを確認**（特に 9-10、10-11、11-12）。
5. 線が動くと簡単にパッドごと剥がれるので、**エポキシか UV レジンで根元を固定**する。
   これをやらないと実験中にほぼ確実に断線する。

**ピンヘッダ・ブレッドボードについて**

- **2.54mm ピンヘッダは立てられない**。列間 12.00mm はユニバーサル基板の
  2.54mm グリッド（4×2.54 = 10.16mm、5×2.54 = 12.70mm）に乗らない。
- **1.27mm グリッドにも乗らない**（12.00 / 1.27 = 9.449）。
- 1.27mm ピッチの 1×6 ピンヘッダを両辺に立てること自体は可能だが、
  そこから先を汎用基板で受けられないので、実験段階では旨味が薄い。
- 公式も **"castellated-hole SMT mounting"（SMT リフロー実装）としか書いておらず、
  ピンヘッダに関する記述は一切ない**（§7.4）。そういう使い方は想定外。
- **落としどころ（推奨）**:
  - (a) **線を直付け**して反対側を 2.54mm ヘッダに立てた小基板へ持っていく（最速）
  - (b) 変換基板を起こす。JLCPCB 等で 5 枚 $2 程度。
    その場合 M5Stack のランドパターンは基板端から外へ 0.387mm しか出ておらず
    手はんだにはやや不足なので、**外側へ 0.8〜1.0mm 程度延ばす**とフィレットが
    見えて作業しやすい（推奨。M5Stack 純正の寸法ではない）。

### 3.5 うまくいかないとき

`GETTING_STARTED.md` の切り分け表を使う。半田パッド固有の追加チェック:

| 症状 | 疑うところ |
|---|---|
| `0xFFFFFFFF` / `0x00000000` | 予備はんだが切り欠きに乗っておらず、被覆越しに触っているだけ |
| 触ると値が変わる | 根元が剥がれかけ。固定剤で補強してやり直す |
| 隣接信号が連動する | 半田ブリッジ。特に 9-10-11-12 |
| 16MHz で不安定、4MHz なら安定 | 配線長・GND 戻り経路。GND を pin 8 と pin 12 の 2 本にする。<br>それでも駄目なら `boards/*.h` の `spi_fast_hz` を 8MHz / 4MHz に落とす |
| 測距距離が極端に短い | アンテナ側 3.5mm に金属／配線がある |

## 4. 経路C: M5StampS3A 背面 12P FPC（StampFly）

**StampFly に載せるタグはこの経路を使う。**（2026-08-22 決定。旧 GROVE 4線
構成は廃案。ピン定義とその根拠の全文は `boards/stampfly.h` にある。）

M5StampS3A は背面に TFT 用の FPC インタフェースを予約しており、
**0.5mm の 8P と 12P、2通りのフットプリントが用意されている（出荷時はどちらも
未実装）。12P 版に 0.5mm 12P コネクタを後付けする。**

| 位置 | ネット | GPIO | 割当 |
|-----:|--------|------|------|
| 1 | VIN_5V | — | 使わない（低ノイズ化で LDO を積むならここから） |
| 2 | GPIO18 | G18 | 未配線（GP7 用に空けてある） |
| 3 | GPIO17 | G17 | DW_WAKEUP |
| 4 | GPIO16 | G16 | **DW_IRQ** |
| 5 | BL_3V3 | — | **使わない（下記）** |
| 6 | GND | — | GND |
| 7 | DISP_RST | G33 | DW_RSTn |
| 8 | DISP_RS | G34 | DW_CDO (MISO) |
| 9 | DISP_MOSI | G35 | DW_CDI (MOSI) |
| 10 | DISP_SCK | G36 | DW_CLK (SCK) |
| 11 | VDD_3V3 | — | **VCC_3V3（電源はここ）** |
| 12 | DISP_CS | G37 | DW_CSn |

出典: M5Stack 公式回路図 `assets/Sch_StampS3_v0.3.3.pdf`。図面のラスタ化に
よる目視読取と、ベクターパスの色・座標追跡による独立再構成の2通りで
同じ結果を得ている。

**必ず守ること:**

1. **電源は「位置 11」の VDD_3V3 から取る。「位置 5」の BL_3V3 は使わない。**
   BL_3V3 はロードスイッチ **AW35122FDR (U2)** の出力で、その EN が
   **G38 (DISP_BL)** に配線されている。さらに StampS3A ではこの BL_3V3 が
   オンボード RGB LED の電源も兼ねている。ここから給電すると
   **UWB モジュールの電源が G38 の状態に従属し、G38 が Low になるたびに落ちる**。
   VDD_3V3 はそのロードスイッチの**上流**なので G38 と無関係。
2. **G38 はどちらのコネクタにも出ていない。** U2 の EN にしか配線されて
   いないので FPC 経由では掴めない。もっとも GPIO は 8 本あるので必要ない。
3. **「位置」は端から数えた並び順であって、回路図上のピン番号ではない。**
   無印 StampS3 の回路図(v0.2)と StampS3A の回路図(v0.3.3)は**番号を振る
   向きが逆**（v0.2 は VIN_5V=1、v0.3.3 は VIN_5V=12）だが、**ネットの
   並び順は 1 本もずれていない**。設計の基準は番号ではなく並び順に置くこと。
   絶対位置は実物で1回だけ確定させる: 目的のパッドと M5StampS3A 側面の
   **5V パッド**または **3V3 パッド**との導通を測れば、VIN_5V 端と
   VDD_3V3 端が一意に決まる（両者は反対側にある）。
4. **8P 版では GPIO が 5 本 (G33〜G37) しか取れない。** SPI 4 本 + 1 本に
   しかならないので、**必ず 12P 版を実装すること**。両者は同一パッド列を
   共有するフットプリントの選択肢なので、12P を付ければ 8P を兼ねる。

**この経路の利点**: StampFly が使っている GPIO と 1 本も重ならない
（G16/G17/G18 は側面 23 ピンに出ておらず、G33〜G37 も同様）。飛行系の
SPI2 とバスを共有しないので、UWB ドライバが SPI をハングさせても IMU は
止まらない。GROVE 2 系統も丸ごと空く。電源も降圧不要になる（旧 GROVE 経路は
電池電圧 約4.35V が直結で、絶対最大定格 4.0V を超えるため LDO 必須だった）。

## 5. 全経路共通の禁止事項

### 5.1 5V を入れない

**公式仕様は 3.3V。パッド 2（VCC_3V3、FPC 1/2）は QM33120W の電源レールに
直結しており（実物確認 + 公式回路図で確認済み、§7.3）、動作範囲 2.4〜3.6V・
絶対最大定格 4.0V**（`docs/refs/QM33120W_DS.txt:553, 567-569`）。

- **3.3V 供給を推奨。3.6V 超は仕様外。4.0V 以上は破損の恐れ。5V は不可**（入れると壊れる）。
- GROVE などから電源を取る場合は、**先にその GROVE の実際の電圧を実測**する。
  M5Stack 製品の GROVE は 5V 出力のものが多く、**そのままでは繋げない**。
  StampFly の GROVE は電池直結で満充電でも約 4.35V あり、これも**絶対最大定格 4.0V を
  超えるため直結不可**。3.3V レール（ホスト基板のレギュレータ出力など）から取るか、
  **高 PSRR の LDO か低リップルの電源**を介すこと（以前ここに書いていた「12 mVpp 以内」は QM33120W データシート Rev. D に該当記述がなく根拠不明のため撤回。データシートは「電源リップル分の余裕を設計で考慮せよ」とだけ述べている。2026-08-29 確認）。
- 消費電流はデータシート値で **スリープ 75.9µA / アンカー 5.23mA / タグ 58.0mA @3.3V**。
  瞬時ピークは QM33120W データシート Rev. D p.11 の連続試験モード値で **TX ch9 最大 76 mA / RX ch9 最大 107 mA**
  （単一フレーム平均は 47 µF 付きで 17〜19 mA）。**ホストの 3V3 レギュレータに 150 mA 程度の余裕**と、
  **モジュール直近のバルク容量（推奨 10 µF、Qorvo の測定条件は 47 µF）**を見ておく（2026-08-29 更新）。
- USB 給電中は問題になりにくいが、**バッテリ運用に移す前に 3V3 レールの電圧降下を実測**すること。

回路レベルの詳細（VDD1/VDD2/VDD3 とネットの対応など）は §7.3 参照。

### 5.2 アンテナ禁止領域

フットプリントには F.Cu / B.Cu 両面に **keepout zone** が定義されている
（`tracks not_allowed / vias not_allowed / pads not_allowed / copperpour not_allowed`）。

```
矩形: x -5.969 … +6.096 （基板全幅）,  y -6.985 … -3.429
→ アンテナ側の端から 3.556 mm、基板全幅にわたる帯
```

出典: `Stamp_UWB.kicad_mod` の 2 つの `(zone ... (keepout ...))` ブロック。

**公式も同趣旨の注意を書いている**（FPC 使用時の話だが、アンテナが
**基板パターンアンテナ**であることと、その下に導体を通すなという指示が明確）:

> "consider the impact of the FPC cable and its connector on the module antenna
> performance. **Do not route the FPC cable beneath the module's PCB antenna**…"
> — https://docs.m5stack.com/en/arduino/projects/stamp/stamp_uwb

→ **半田付けの飛び線でも同じことが言える。**
配線をモジュールの下（アンテナ側の真下）に這わせないこと。

**実験時の含意（推奨）**
- モジュールを板やケースに固定するとき、**面取りのある側 3.5mm 以上には
  金属・グランド・配線・電池・カーボンを置かない**。
- 配線を引き出すときも、この帯の上を線が横切らないようにする
  （引き出しは pin 6 / pin 7 側＝面取りと反対の端へ逃がす）。
- ドローンに載せる際も同様。フレームのカーボンはアンテナを大きく劣化させる。

### 5.3 RSTn に外付けプルアップを付けない

- `components/uwb_port/src/uwb_port.c` の実装は、**RSTn を能動的に High へ
  駆動しない**。初期化時 `GPIO_MODE_INPUT`（ハイインピーダンス）にし、
  リセット時だけ出力 Low を出して、また入力へ戻す
  （`uwb_port_hard_reset()`）。
- QM33120W データシートは RSTn について「**Must not be pulled high by the
  external source**（外部から High へプルしてはならない）」と明記しており、
  High 側は **IC 自身の POR（Power-On-Reset）回路が駆動**する設計。
  外付けプルアップも、ホスト側 GPIO の内部プルアップ有効化も**不要かつ仕様違反**。
- RSTn が浮いたままリセットが解除されないように見える場合は、プルアップ不足では
  なく **UWB チップ側が前回の状態（受信中など）を引きずっている**ことを疑う。
  RST 未配線の構成では `begin()` 内のソフトリセット（`dwt_softreset()` +
  `dwt_checkidlerc()` 待ち。§7.4 の外部報告と `docs/REVIEW_2026-08-21.md` §1 M-2）
  で復旧する設計になっている。
- **回路図で裏付け済み**: 上記の結論（ホスト側にプルアップ不要）は
  推測ではなく確認済みである。**モジュール自体に R1 (10kΩ, VCC_3V3 へ) + C15
  (1µF, GND へ) の RC が RSTn に付いている**（時定数 ≈10ms。§7.3）。これは
  「外部の強い駆動源で High へプルしてはならない」というデータシートの注意とは
  矛盾しない（弱い抵抗プルアップ + ホストの open-drain Low 駆動という組み合わせは
  一般的な作法であり、M5Stack 自身がモジュール上でこの構成を採っている）。
  **したがってホスト側でさらにプルアップを重ねる必要はない。**

### 5.4 外付け部品（推奨）

いずれも **推奨**であって、M5Stack の要求仕様ではない。

- モジュール上にはコンデンサが 24 個載っており、内部のデカップリングは
  一通り入っている（STEP モデルに加え、**回路図でも確認済み** — §7.3。
  VDD1/VDD2a/VDD2b 各レール直近と JW5712 周辺に個別のバイパスコンデンサがある）。
- ただし **飛び線で給電すると配線インダクタンスが乗る**ので、
  **pin 2 (3V3) と pin 1 (GND) の直近に 10µF(セラミック) + 0.1µF を追加**する。

### 7.1 パッド ↔ FPC ピン対応表（正本）

**パッド（キャステレーション、シンボル `PINMAP`）と FPC コネクタ（シンボル `J1`。
S017 では未実装 = NC、S017-F でのみ実装）は別のピン番号体系である**。公式回路図で
確認したところ、**信号名は同一だが番号の並びが違う**。パッドと FPC で並びが違う
だけで、**両方とも正しい**。**FPC ケーブルで接続する場合は必ず FPC 側の番号
（下表右列）で配線すること。パッド番号をそのまま流用しない。**

| パッド番号（PINMAP） | 信号 | 列 | FPC 番号（J1、S017-F のみ実装） | 用途 | 必要度 |
|:-:|---|---|:-:|---|:-:|
| 1 | GND | 左 | 7 | グランド | ○ |
| 2 | VCC_3V3 | 左 | 1, 2 | **公式 3.3V。チップ直結、絶対最大定格 4.0V。5V 不可（§5.1）** | ● |
| 3 | DW_WAKEUP | 左 | 5 | ウェイクアップ制御 | △ |
| 4 | DW_IRQ | 左 | 4 | 割り込み出力 | ● |
| 5 | DW_GP7 | 左 | 3 | チップ GPIO7 / SYNC（予備） | |
| 6 | DW_RSTn | 左 | 6 | リセット（負論理） | ● |
| 7 | DW_CDO (MISO) | 右 | 8 | SPI **MISO** | ● |
| 8 | GND | 右 | — | グランド | ● |
| 9 | DW_CDI (MOSI) | 右 | 9 | SPI **MOSI** | ● |
| 10 | DW_CSn | 右 | 10 | SPI **CS** | ● |
| 11 | DW_CLK (SCK) | 右 | 12 | SPI **SCK** | ● |
| 12 | GND | 右 | 11 | グランド | ● |

● = 必須 / ○ = どれか1本 GND があればよい / △ = 省電力運用時のみ

**パッドは GND×3 (1/8/12) ・VCC_3V3×1 (2)、FPC は GND×2 (7/11) ・VCC_3V3×2 (1/2) と本数も異なる。**
**混ぜると電源が信号線に入って壊れる。**

出典: `Stamp_UWB.kicad_sym`、公式回路図 PDF（`assets/SCH_UWB_MODULE_SCH_main_V0.2_...pdf`）の
ネットリスト（J1・PINMAP 双方）、`docs/archive/SURVEY_m5stamp_uwb_module.md` の対応表。
三者は完全に一致している。

**配置上の利点**: 右列（pin 7〜12）だけで **MISO / GND / MOSI / CSn / CLK / GND** が揃う。
SPI の 4 本が 2 本の GND に挟まれる並びなので、**右列 6 本をまとめてリボン状に引き出すと
戻り電流経路が短くなり、16MHz でも比較的素直に通る**（推奨。実測で確認すること）。

**参考（本リポジトリの配線ではない）**: 外部報告（§7.4）ではパッド 2=3V3、1/8/12=GND、
11=SCK、7=MISO、9=MOSI、10=CS の 6 本だけで動作を確認している。RST/WAKEUP/IRQ/GP7 は未配線。

### 7.3 電源系統（公式回路図より）

出典: `assets/SCH_UWB_MODULE_SCH_main_V0.2_20251128_2026_06_01_11_54_35.pdf`
（M5Stack 公式回路図 V0.2、2025-11-28 配布。ユーザが取得しリポジトリに配置）。

**チップの電源ピンとネットの対応:**

| チップピン | 接続先ネット | 電圧範囲（データシート） |
|---|---|---|
| VDD1 (B13) | VCC_3V3（**パッド 2 に直結**） | 動作 2.4〜3.6V、絶対最大 4.0V |
| VDD2a (F15) | VCCA_3V3（VCC_3V3 を FB1 フェライトビーズ 600Ω@100MHz 経由。DC 的には同電位） | 動作 2.4〜3.6V、絶対最大 4.0V |
| VDD2b (B15) | VCC_3V3（**パッド 2 に直結**） | 動作 2.4〜3.6V、絶対最大 4.0V |
| VDD3 (D15) | VCC_1V8（**唯一 JW5712 の DC-DC 出力から来るレール**。パッド 2 には非依存） | 本節対象外 |

**VDD1 と VDD2b の 2 系統がパッド 2 に直結**しており、VDD2a も同じ VCC_3V3 をフェライト
ビーズ越しに受けている（フェライトビーズは高周波ノイズ抑制用で、DC ではほぼ 0Ω）。
**DC-DC（JW5712）の出力を受けているのは VDD3（1.8V 系）だけ**であり、
「DC-DC 出力だけがチップに入る」という構成では **ない**。モジュール上の JW5712
（VIN=VCC_3V3、VSEL1=GND/VSEL2=VCC_3V3/VSEL3=GND で 1.8V 出力に設定、
**EN=DW_EXTON**＝チップ動作中のみ有効化）は **VDD3（1.8V 系）専用**であり、
パッド 2 に入れる電圧の上限を広げてはくれない。EN が DW_EXTON に配線されているため、
**チップが SLEEP 中は VCC_1V8（VDD3）が落ちる**（PCB 上に VCC_3V3⇔VCC_1V8 間の
ブリッジ抵抗 R3 もあるが実装は NC）。

**J1（FPC コネクタ）と PINMAP（パッド）のピン番号体系の違いは §7.1 参照。**
回路図には 2 つのコネクタシンボルがあり、`J1` は S017 では NC（未実装）、
`PINMAP` は S017/S017-F の両方にある。本プロジェクトが使うのは `PINMAP`（パッド）。

**RSTn**: R1（10kΩ、VCC_3V3 へ）+ C15（1µF、GND へ）の RC が付いている
（時定数 ≈10ms）。外付けプルアップ禁止の理由は §5.3 参照。本リポジトリの
`hardReset()` 既定（Low 5ms → 解放後 100ms 待ち。
`components/uwb_qm33120/include/uwb_qm33120.hpp:58`）は τ=10ms に対して十分な待ち時間。

**IRQ**: R2（10kΩ、VCC_3V3 へ）のプルアップが付いている。チップの IRQ は既定で
アクティブ HIGH の push-pull 出力なので、動作中は問題にならない。しかし
**SLEEP/DEEPSLEEP でピンが Hi-Z になると、この 10kΩ プルアップにより IRQ ピンは
H に張り付く**。QM33120W データシートには「sleep するには IRQ が low/inactive で
なければならない」旨の記載があり、この外付けプルアップはその注意と逆方向に働く。
`components/uwb_port/src/uwb_port.c` の GPIO 設定は当初 `GPIO_INTR_POSEDGE` +
内部プルダウン（約45kΩ）だったが、モジュール上の 10kΩ プルアップの方が強く効くため
内部プルダウンは実質無意味（2026-08-21 に `GPIO_PULLDOWN_DISABLE` に修正。詳細は
`docs/IRQ_POLICY.md`）。SLEEP/WAKEUP を積極的に使う設計にする場合は要再検討
（現状の IRQ 利用はアンカー側の起床信号のみで、チップを SLEEP させる運用は
していないため実害はない）。

**その他:**
- **水晶**: X1 = SX0B38.400F0810F30（38.4MHz）、負荷容量 C18/C19 = 3.3pF × 2。
- **アンテナ**: RF1 側がアンテナ（C5 を直列に挟んで基板パターンアンテナへ。
  整合用 C20 = 1.5pF、C21/C22 は NC）。**RF2 側は未使用で C24 = 49.9Ω で終端**
  （送受を RF1 に集約した構成と読める）。
- **DW_GP7** はパッド 5 に直結（プルなし）。**DW_WAKEUP** はパッド 3（PINMAP 側）/
  FPC pin 5 に直結（プルなし）。
- コンデンサ 24 個の内訳: 電源デカップリング（VDD1/VDD2a/VDD2b 各 1 個 +
  JW5712 周辺 5 個 + VIO_D/VTX_D）、水晶負荷 2 個、RF 整合/終端 3 個、RSTn の C15、他。
