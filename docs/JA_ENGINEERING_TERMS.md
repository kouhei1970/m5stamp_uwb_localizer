# 言葉遣いの辞書（日本語技術文書の言い換え表）

**このリポジトリの文書（README・docs）で使わない語と、その言い換えの正本。**
文書を書く・直す前に一度ここを引く。用語（略語・専門用語）の意味は
[`GLOSSARY.md`](GLOSSARY.md)、文書全体の約束ごとは [`README.md`](README.md) にある。

制定: 2026-09-05（README・docs 全体の是正と同時に作成。経緯は `git log -- docs/JA_ENGINEERING_TERMS.md`）。

## 1. 原則

1. **装置・タスク・ソフトウェアが主語のときは、比喩ではなく実際の動作を書く。**
   人や動物のように言わない（気づく・諦める・死ぬ・眠る・黙る・信じる など）。
2. **英語の直訳語・業界スラングを使わない。** 日本の技術者が日常的に使う語に置き換える。
3. **略語は各文書で初めて出たときに「正式名称（英語）＝日本語の意味」を添える。**
   例: DS-TWR（Double-Sided Two-Way Ranging、両側二方向測距）。2 回目以降は略語だけでよい。
4. **統計の「回帰」（回帰分析・回帰直線）と「期待値」は対象外。** ソフトウェアの
   regression（変更で既存機能が壊れること）だけを「退行」と言う。
5. 文書内の文体（です・ます／である）は 1 つに揃える。

## 3. 残してよい定訳（初出で説明を添える）

| 語 | 扱い |
|---|---|
| 相手局・自局 | 通信の標準用語。裸の「相手」「自分」は使わない |
| スリープ | OS の標準用語（「眠る」「目覚める」は使わない） |
| スタベーション | 初出で「処理が回ってこない状態（スタベーション）」と書き、以後は「処理が回ってこない」 |
| ゾンビ接続 | 初出で「切断されたのに残り続ける接続（いわゆるゾンビ接続）」と書き、以後は「残留接続」 |
| ボトルネック | 「律速」の代わりに使う |
| フック・トリガ・ハンドル | コードの識別子（例: `RangingSampleHook`）や API 名を指すときだけ。文中の動作説明では「呼び出し」「作動」「操作」を使う |

## 4. 使い方

- 新しい文書やコミットメッセージを書く前に §2 を一度読む。
- 一括で点検するときは `grep -n` で §2 の語を README.md と docs/*.md に当て、
  装置主語のものだけを直す（人が主語の「気づく」「知らない」は対象外）。
- 指摘された語はまず §2 に追加してから本文を直す（辞書が先、本文が後）。
- コード内コメントにはまだ適用していない（2026-09-05 時点）。適用するときも同じ表を使う。
