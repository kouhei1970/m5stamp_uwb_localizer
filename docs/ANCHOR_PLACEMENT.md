# アンカー配置の設計指針

Phase 4 Step 1 の検証で、**アンカー配置が測位の成否を直接左右する**ことが実証できた。
実機を触る前に配置ルールを決めておく。

## 実測（ホスト上、components/uwb_loc を直接呼んで確認）

条件: アンカー4台を 4m × 3m の長方形の四隅に**同一平面**で置く。
真値 = (1.700, 1.100, 0.900)。測距値は真値からの理論距離（ノイズなし）。

| アンカー平面 | `uwb_anchors_coplanar()` | Lv0 の解 | Lv2 の解 |
|---|---|---|---|
| **z = 0.0** | 1 (検出) | ok=1, (1.700, 1.100, **0.000**) | **ok=0（解けない）** |
| z = 2.4 | 1 (検出) | ok=1, (1.700, 1.100, **0.000**) | ok=1, ambiguous=1, (1.700, 1.100, **0.900**) ✓ |
| z = -1.5 | 1 (検出) | ok=1, (1.700, 1.100, **0.000**) | ok=1, ambiguous=1, (1.700, 1.100, **0.900**) ✓ |
| **z = 0.001** | 1 (検出) | ok=1, (1.700, 1.100, **0.000**) | ok=1, ambiguous=1, (1.700, 1.100, **-0.898**) ← **鏡像解** |

## 読み取れること

1. **同一平面配置だと3Dの高さが決まらない。** これは幾何的に当然で、
   アンカー平面に対して対称な2つの解（鏡像解）が存在する。
2. **Lv0（LLS三辺測量）は同一平面だと高さを一切復元できない。**
   平面の z によらず z=0 を返す（リッジ正則化つき最小ノルム解が z を潰す）。
   → **同一平面配置で Lv0 の高さを信用してはいけない。**
3. **Lv2 は鏡像解のどちらかを返す。どちらが返るかは配置と初期値次第。**
   z=0.001 のケースでは真値 +0.9 に対して **-0.898** を返した。
   → **`ambiguous` フラグを必ず見ること。** 1 なら高さは信用できない。
4. **アンカー平面がワールド原点を通る（z=0）と Lv2 は `ok=0` で完全に失敗する。**
   Beck法が同一平面で特異判定 → LLS にフォールバック → その解が z≈0 に寄る →
   アンカー平面も z=0 なので全観測の z 方向ヤコビアンが厳密ゼロ →
   Gauss-Newton が動けず共分散が特異 → 逆行列失敗、という連鎖。

## 配置ルール（本プロジェクトの決定）

### 必須
- **3D 測位をするなら、アンカーを同一平面に置かない。**
  最低1台は他と違う高さにする（例: 3台を床付近、1台を天井付近）。
  台数に余裕がある（5台以上）なら、高さを2段以上に散らす。
- **`uwb_anchors_coplanar()` を起動時に必ず呼び、真なら警告を出す。**
  そのまま3Dで解かせない。
- **`uwb_fix.ok` と `uwb_fix.ambiguous` の両方を必ず見る。**
  `ambiguous=1` の解の高さは使わない。

### 同一平面配置を避けられない場合
- `uwb_config.dim = 2` + `z_fixed` に倒す（高さは既知として固定）。
  水平位置は同一平面配置でも正しく出る（上の表でも x,y は全ケース正確）。
- または `use_z_bounds` で z を物理的にあり得る範囲に制限し、鏡像解を弾く。

### ワールド座標系の取り方
- **アンカー平面がワールド原点を通らないようにする。**
  z=0 ちょうどは Lv2 が失敗する。床にアンカーを置くなら、
  原点を床から少しずらす（例: 床を z=0.1 にする）か、原点を天井側に取る。
- StampFly の屋内飛行を考えると「アンカーを床に並べる」は最もやりがちな配置で、
  かつ**最悪のケース**（同一平面 かつ 原点を通る平面）になる。要注意。
