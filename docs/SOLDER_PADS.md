### 1.2 キャステレーションであることの根拠

**公式製品ページが明言している**（1.1 節の引用）。
さらに設計データ 3 つが整合し、寸法まで裏付けが取れている。

1. **STEP モデル**: 半径 0.25mm（**φ0.5mm**）の円筒穴が 12 個、
   x = ±6.000 mm に **y = −1.85 / −0.58 / 0.69 / 1.96 / 3.23 / 4.50 mm**
   （= ピッチ **1.27mm**）で並び、z = 0.000〜0.624 mm（基板を貫通）。
2. **同 STEP の基板外形**が x = ±6.013 mm。
   → 穴の中心より **0.013mm だけ外**を外形線が通る＝**穴のほぼ真ん中で切断**。
   残る切り欠きは **開口幅 約0.50mm × 深さ 約0.26mm × 高さ 0.62mm**。
3. **フットプリント**（Altium/KiCad とも）は同じ位置に
   **ドリル径 0（= SMD ランド）** のパッド 12 個。
   相手基板側にはドリルを開けない＝キャステレーション実装用のランドパターン。

→ **側面から半田付けできる**。ジャンパ線の直付けが可能。

**傍証**: 同じリポジトリの `Stamp-S3-SMD.kicad_mod`（M5Stamp S3 の SMD 実装用
ランドパターン）も **1.27mm ピッチ**の SMD ランドが両辺に並ぶ同型式で、
M5Stamp S3 は公式に側面キャステレーションを持つ。**Stamp シリーズ共通の作法**。
ただし Stamp S3 のランドは 1.8 × 0.8mm と外側へ大きく張り出しているのに対し、
**M5Stamp UWB Module は 0.8 × 0.6mm と最小限**である（4.4 節の変換基板の話に関係する）。

### 1.3 寸法（フットプリント原点基準、KiCad 座標系 +Y は下）

> 1.2 節で引用した数値は **STEP（機械系、+Y は上）** の座標、
> 本節は **KiCad フットプリント**の座標。両者は
> `STEP_x = KiCad_x − 0.1`, `STEP_y = −KiCad_y + 1.55` の関係で
> 完全に一致することを確認済み（12個のパッド全てで検算）。
> **相対寸法（ピッチ・列間・外形）はどちらの系でも同じ。**

**公式カタログ値は「11.5 × 12.0 × 1.6 mm」。**
下の実測（設計データからの抽出）12.026 × 11.526 mm と一致する
（公式は 11.5 = パッド列が並ぶ方向、12.0 = 2列を跨ぐ方向）。
**1.6 mm は部品込みのモジュール全高**であって基板厚ではない。
S017-F はこれが **2.8 mm**（背面の FPC コネクタ分 +1.2mm）。

```
基板外形 : x  -5.913 … +6.113  (幅 12.026 mm ≒ 公式 12.0)
           y  -6.963 … +4.563  (高さ 11.526 mm ≒ 公式 11.5)
基板厚   : 約 0.62 mm（3Dモデルより。モジュール全高 1.6mm とは別物）
パッド左列 (pin 1-6)  : x = -5.900
パッド右列 (pin 7-12) : x = +6.100      → 列間 12.000 mm
パッド y : -2.95 / -1.68 / -0.41 / +0.86 / +2.13 / +3.40  (ピッチ 1.27)
ランド寸法: 0.6 × 0.8 mm, 角丸矩形(rratio 0.25), 回転270°
           → 辺に沿う方向 0.6mm / 辺と直交する方向 0.8mm
           （基板端から外側へ 0.387mm、内側へ 0.413mm はみ出す）
```

### 1.4 平面図（モジュール上面から見た配置）

```
     ← 12.026 mm →
   ／‾‾‾‾‾‾‾‾‾‾‾‾‾＼          ← 角の 2.0×2.0mm 面取り（pin1 側だけ大きい）
  ／                ＼
 ┌──────────────────┐  ┐
 │ ■■■■■■■■■■■■■■■■ │  │  ← アンテナ用 銅箔禁止領域
 │ ■  ANT KEEPOUT  ■ │  │     表裏とも tracks/vias/pads/copper 全面禁止
 │ ■■■■■■■■■■■■■■■■ │  │     幅=基板全幅, 深さ 3.556 mm
 ├──────────────────┤  ┤     (基板端から 3.53mm)
 ◖1  GND      GND 12◗  │
 ◖2  3V3      CLK 11◗  │  11.526
 ◖3  WAKEUP   CSn 10◗  │   mm
 ◖4  IRQ      CDI  9◗  │            ◖ ◗ = キャステレーション φ0.5
 ◖5  GP7      GND  8◗  │                 ピッチ 1.27 mm
 ◖6  RSTn     CDO  7◗  │
 └──────────────────┘  ┘
   ↑ 左列 pin1→6 が下向き    ↑ 右列 pin7→12 が上向き（反時計回り）
```

- **pin 1 の側の角に 2.0mm × 2.0mm の 45° 面取り**がある（他の 3 隅は 0.2mm のみ）。
  → **向きを間違えないための鍵**になる。
- 面取り側の端 = **アンテナ側**。
- pin 1 中心はアンテナ側の端から **4.013 mm**、pin 6 中心は反対側の端から **1.163 mm**。

> **左右の向きについての注意**: 上図は KiCad フットプリント（相手基板の表面
> = F.Cu 層）をそのまま上から見た図である。モジュールを相手基板の上に
> 部品面を上にして載せる通常の実装であれば、**モジュールを上から見た図と一致する**。
> ただし **モジュールのどちらの面が部品面かは本調査では確定できていない**ので、
> 実物では 4.1 節の導通チェックで向きを検証すること
> （キャステレーションは側面に出ているので、表裏どちらから見ても
> パッドの物理位置自体は変わらない。変わるのは左右の見え方だけ）。

### 1.5 アンテナ禁止領域（重要）

フットプリントには F.Cu / B.Cu 両面に **keepout zone** が定義されている
（`tracks not_allowed / vias not_allowed / pads not_allowed / copperpour not_allowed`）。

```
矩形: x -5.969 … +6.096 （基板全幅）,  y -6.985 … -3.429
→ アンテナ側の端から 3.556 mm、基板全幅にわたる帯
```

出典: `Stamp_UWB.kicad_mod` の 2 つの `(zone ... (keepout ...))` ブロック。

**公式も同趣旨の注意を書いている**（FPC 使用時の話だが、アンテナが
**基板パターンアンテナ**であることと、その下に導体を通すなという指示が明確）:

> "consider the impact of the FPC cable and its connector on the module antenna
> performance. **Do not route the FPC cable beneath the module's PCB antenna**…"
> — https://docs.m5stack.com/en/arduino/projects/stamp/stamp_uwb

→ **半田付けの飛び線でも同じことが言える。**
配線をモジュールの下（アンテナ側の真下）に這わせないこと。

**実験時の含意（推奨）**
- モジュールを板やケースに固定するとき、**面取りのある側 3.5mm 以上には
  金属・グランド・配線・電池・カーボンを置かない**。
- 配線を引き出すときも、この帯の上を線が横切らないようにする
  （引き出しは pin 6 / pin 7 側＝面取りと反対の端へ逃がす）。
- ドローンに載せる際も同様。フレームのカーボンはアンテナを大きく劣化させる。

### 1.6 その他の観察

- STEP モデル上、基板を貫通する **φ0.4 mm の穴が 4 個**ある。
  位置は基板中心から左右対称に ±2.1 mm / ±2.7 mm、
  高さ方向は **pin 1 / pin 12 の少しアンテナ寄り（アンテナ禁止領域との境界のすぐ内側）**。
  **用途は 3D モデルからは判別できない**（ビアか、位置決めか、テストポイントか）。
- STEP に含まれる部品リファレンス: `U1, U2, X1, L1, FB1, R1-R3, C1〜C24`。
  **コネクタ (J*) は 3D モデルに含まれていない。**
  → このモデルが「FPC コネクタ未実装の S017」を表しているのか、
    単に 3D モデルが省略されているだけなのかは**判断できない**。
- コンデンサが **24 個**実装されている → モジュール内のデコップリングは
  一通り入っていると考えてよい（ただし回路図で未確認、下記 5 章参照）。
- **S017-F の FPC コネクタは「背面（rear）」に実装されている。**
  > "Rear Expansion Interface: FPC 0.5mm-12P" /
  > "A 0.5mm-12P FPC connector is **pre-soldered on the back**"
  > — https://shop.m5stack.com/products/m5stamp-uwb-module-with-fpc-qm33120w

  → **S017-F は背面が平らではない**（厚み 1.6mm → 2.8mm）。
  半田パッドで使う場合、**コネクタのある面を下にしてベタ貼りはできない。**
  コネクタ側を上（または逃がしを作る）にして固定すること。

## 2. パッド ↔ FPC ピン対応表

**パッド番号と FPC ピン番号は同一**（同じシンボル `PINMAP` の同じピン番号に
フットプリントのパッド番号が対応するため）。信号名も同一。

| パッド / FPC pin | 信号 | 列 | 用途 | 最小配線 | 推奨配線 |
|---:|---|---|---|:-:|:-:|
| 1 | GND | 左 | グランド | | ○ |
| 2 | **VCC_3V3** | 左 | **電源 3.3V 単一** | ● | ● |
| 3 | DW_WAKEUP | 左 | ウェイクアップ制御 | | △ |
| 4 | DW_IRQ | 左 | 割り込み出力 | | ● |
| 5 | DW_GP7 | 左 | チップ GPIO7 / SYNC（予備） | | |
| 6 | DW_RSTn | 左 | リセット（負論理） | | ● |
| 7 | DW_CDO | 右 | SPI **MISO** | ● | ● |
| 8 | GND | 右 | グランド | ● | ● |
| 9 | DW_CDI | 右 | SPI **MOSI** | ● | ● |
| 10 | DW_CSn | 右 | SPI **CS** | ● | ● |
| 11 | DW_CLK | 右 | SPI **SCK** | ● | ● |
| 12 | GND | 右 | グランド | | ● |

● = 必須 / ○ = どれか1本 GND があればよい / △ = 省電力運用時のみ

出典（信号名）: `Stamp_UWB.kicad_sym`（上記 URL）、および `docs/SURVEY_m5stamp_uwb_module.md`
（公式回路図 PINMAP より）。両者は完全に一致している。

**配置上の利点**:
右列（pin 7〜12）だけで **MISO / GND / MOSI / CSn / CLK / GND** が揃う。
SPI の 4 本が 2 本の GND に挟まれる並びなので、
**右列 6 本をまとめてリボン状に引き出すと戻り電流経路が短くなり、
16MHz でも比較的素直に通る**（推奨。実測で確認すること）。

## 3. Stamp S3 / AtomS3 との配線表

ホスト側ピン番号は `boards/stamps3.h` / `boards/atoms3.h` の**暫定値**と一致させてある。
**どちらも実配線前に現物と照合すること**（両ファイルの冒頭コメント参照）。

### 3.1 M5Stamp S3（推奨）

| UWB パッド | 信号 | Stamp S3 | 備考 |
|---:|---|---|---|
| 11 | DW_CLK | **G12** | FSPICLK（IO_MUX ネイティブ） |
| 9 | DW_CDI | **G11** | FSPID（MOSI） |
| 7 | DW_CDO | **G13** | FSPIQ（MISO） |
| 10 | DW_CSn | **G10** | CS はソフト制御 |
| 6 | DW_RSTn | **G6** | 通常は入力（Hi-Z）、リセット時のみ Low |
| 4 | DW_IRQ | **G7** | ポーリング動作なら省略可 |
| 3 | DW_WAKEUP | **G8** | 省電力を使わないなら省略可 |
| 5 | DW_GP7 | **（未配線 / boards/stamps3.h は UWB_PORT_PIN_UNUSED）** | 未使用。配線不要 |
| 2 | VCC_3V3 | **3V3** | **5V ピンには絶対に繋がない** |
| 8, 12, 1 | GND | **GND** | 最低 8 と 12 の 2 本を GND へ |

### 3.2 M5 AtomS3

| UWB パッド | 信号 | AtomS3 | 備考 |
|---:|---|---|---|
| 11 | DW_CLK | **G7** | 底面ヘッダ |
| 9 | DW_CDI | **G6** | 底面ヘッダ |
| 7 | DW_CDO | **G5** | 底面ヘッダ |
| 10 | DW_CSn | **G8** | 底面ヘッダ |
| 6 | DW_RSTn | **G1** | Grove SDA を転用（Grove I2C は使えなくなる） |
| 4 | DW_IRQ | **G2** | Grove SCL を転用 |
| 3 | DW_WAKEUP | — | **未配線**（CS パルスでのウェイクにフォールバック） |
| 5 | DW_GP7 | — | 未配線 |
| 2 | VCC_3V3 | **3V3** | **Grove の 5V から取らないこと** |
| 8, 12, 1 | GND | **GND** | |

> AtomS3 は空き GPIO が少ないため WAKEUP/GP7 は未配線。
> `components/uwb_port` は `UWB_PORT_PIN_UNUSED` を扱えるので追加対応は不要
> （`boards/atoms3.h` のコメント参照）。

### 3.3 配線しないパッドの扱い（`boards/*.h` の設定）

半田付けは本数を減らすほど楽なので、最初は **7〜10本**で始めるのがよい。
そのとき **`boards/*.h` 側も実配線に合わせる**こと。

| 配線しないもの | `boards/*.h` の扱い | 理由 |
|---|---|---|
| pin 5 (GP7) | **`.pin_gp7 = UWB_PORT_PIN_UNUSED` にする** | 未配線のまま GPIO 番号を入れておくと入力が浮く。<br>現状 `uwb_port_read_gp7()` を呼ぶファームは無いので実害は出ていないが、<br>合わせておくのが安全 |
| pin 3 (WAKEUP) | `UWB_PORT_PIN_UNUSED` にしてよい | ホスト側は出力なので浮いても害はない。<br>未設定時は CS パルスによるウェイクにフォールバックする<br>（`uwb_port_wakeup_device_with_io()`） |
| pin 4 (IRQ) | `UWB_PORT_PIN_UNUSED` にしてよい | ドライバはポーリング方式。ホスト側は入力なので、<br>番号を残したまま未配線にすると浮く |
| pin 6 (RSTn) | **配線を強く推奨** | `uwb_port_hard_reset()` が使えなくなる。<br>`UWB_PORT_PIN_UNUSED` の場合は待つだけになる |

**Phase 1（`firmware/probe` で `0xDECA0314` を読むだけ）なら
pin 2 / 7 / 8 / 9 / 10 / 11 / 12 の 7 本 + pin 6 (RSTn) の計 8 本で十分。**

### 3.4 電源についての注意

- モジュールは **3.3V 単一供給**。5V を入れると壊れる（`SURVEY_m5stamp_uwb_module.md`）。
- 消費電流はデータシート値で **スリープ 75.9µA / アンカー 5.23mA / タグ 58.0mA @3.3V**。
  TX 瞬時ピークは未公開なので、**ホストの 3V3 レギュレータに 100mA 程度の余裕**を見ておく。
- USB 給電中は問題になりにくいが、**バッテリ運用に移す前に 3V3 レールの電圧降下を実測**すること。

## 4. 半田付けの実務

### 4.1 まずやること（順序）

1. **面取りの大きい角を探して pin 1 を特定**する。
   モジュール裏面のシルクにピン番号が印刷されている可能性が高いが、**未確認**。
   シルクが無ければ 1.4 節の図で向きを決める。
2. **テスターで導通確認**して仮説を検証する。
   - **GND 同士（pin 1 / 8 / 12）の 3 本が互いに 0Ω で導通するか。**
     これが向きの判定に効く。左右反転していれば pin 8 のつもりの所が
     pin 5 (GP7) になり、180° 回転していれば pin 7/2/6 になるので、
     **どちらの誤りもこの 1 つの試験で弾ける**。
   - pin 2（3V3）と GND がベタ短絡（0Ω）していないこと。
     モジュール内にコンデンサが 24 個あるので、抵抗レンジでは
     充電のため最初は低く出て徐々に上がる。**0Ω に張り付かなければ正常。**
   - この 2 点が合えば向きの解釈は正しい。
3. 配線 → 電源投入 → `firmware/probe` で `0xDECA0314` を読む（`BRINGUP.md`）。

### 4.2 電線

- **AWG30 のラッピングワイヤ（芯線 0.25mm / 外径 約0.5mm）か、
  0.2〜0.26mm のポリウレタン被覆線（UEW / エナメル線）**を使う。
  ピッチが 1.27mm しかないので、デュポン線（AWG24〜26）を直付けするのは無理がある。
- UEW を使う場合は、被覆が熱で溶けるタイプ（1UEW/2UEW）でも、
  **予備はんだ時にきちんと被覆が飛んだか目視確認**する。
- **配線長は 10cm 以内**を目安に。SPI 16MHz を通すので長いほど不利。
  すべての線をできるだけ同じ長さで揃え、**GND 線を SPI 線と束ねる**。
- 途中でブレッドボードを挟まない。ブレッドボードの接触抵抗と容量は 16MHz に効く。

### 4.3 半田付け手順（推奨）

1. モジュールを両面テープでまな板（適当な板／耐熱マット）に固定する。
   **アンテナ側（面取りのある端）3.5mm には金属を置かない。**
2. 使うパッドにだけ**フラックスを塗って予備はんだ**を薄く盛る。
   隣接パッドとの隙間は 0.67mm しかないので、盛りすぎない。
3. 線の先端 1mm を予備はんだし、切り欠きに当てて **こて先 1 秒**で付ける。
   こて先は **1.6mm C 型以下**、温度 320〜340℃、鉛フリーなら 350℃程度。
4. 全部付けたら **拡大鏡で隣接ブリッジを確認** → **テスターで隣接ピン間の
   導通が無いことを確認**（特に 9-10、10-11、11-12）。
5. 線が動くと簡単にパッドごと剥がれるので、**エポキシか UV レジンで根元を固定**する。
   これをやらないと実験中にほぼ確実に断線する。

### 4.4 ピンヘッダ／ブレッドボードについて

- **2.54mm ピンヘッダは立てられない**。列間 12.00mm はユニバーサル基板の
  2.54mm グリッド（4×2.54 = 10.16mm、5×2.54 = 12.70mm）に乗らない。
- **1.27mm グリッドにも乗らない**（12.00 / 1.27 = 9.449）。
- 1.27mm ピッチの 1×6 ピンヘッダを両辺に立てること自体は可能だが、
  そこから先を汎用基板で受けられないので、実験段階では旨味が薄い。
- 公式も **"castellated-hole SMT mounting"（SMT リフロー実装）としか書いておらず、
  ピンヘッダに関する記述は一切ない**（1.1 節）。そういう使い方は想定外。
- **落としどころ（推奨）**:
  - (a) **線を直付け**して反対側を 2.54mm ヘッダに立てた小基板へ持っていく（最速）
  - (b) 変換基板を起こす。JLCPCB 等で 5 枚 $2 程度。
    その場合 M5Stack のランドパターンは基板端から外へ 0.387mm しか出ておらず
    手はんだにはやや不足なので、**外側へ 0.8〜1.0mm 程度延ばす**とフィレットが
    見えて作業しやすい（推奨。M5Stack 純正の寸法ではない）。

### 4.5 ハーネス側に載せておくとよい外付け部品

いずれも **推奨**であって、M5Stack の要求仕様ではない。

**(a) パスコン**
- モジュール上にはコンデンサが 24 個載っており、内部のデカップリングは
  一通り入っていると思われる（STEP モデルより。**回路図では未確認**）。
- ただし **飛び線で給電すると配線インダクタンスが乗る**ので、
  **pin 2 (3V3) と pin 1 (GND) の直近に 10µF(セラミック) + 0.1µF を追加**する。

**(b) DW_RSTn のプルアップ（重要）**
- `components/uwb_port/src/uwb_port.c` の実装は、**RSTn を能動的に High へ
  駆動しない**。初期化時 `GPIO_MODE_INPUT`（ハイインピーダンス）にし、
  リセット時だけ出力 Low を出して、また入力へ戻す
  （`uwb_port_hard_reset()`）。**つまりモジュール側のプルアップが前提**。
- **モジュール側にプルアップがあるかは回路図が取得できず未確認**（1.7 節）。
- 対策（どちらでもよい。実物で確認するまでは保険としてやっておく価値がある）:
  - ハーネス上で **pin 6 (RSTn) ↔ pin 2 (3V3) 間に 10kΩ** を入れる、または
  - ホスト側 GPIO の内部プルアップを有効にする
    （`gpio_set_pull_mode(pin_rst, GPIO_PULLUP_ONLY)` を `uwb_port_init()` に追加）。
    ただしこれは `components/` の変更になるので、今回は入れていない。
- RSTn が浮いたままだと、リセットが解除されない／不定に暴れる可能性がある。
  疎通が全く取れないときはここを疑う。

### 4.6 うまくいかないとき

`BRINGUP.md` の切り分け表を使う。半田パッド固有の追加チェック:

| 症状 | 疑うところ |
|---|---|
| `0xFFFFFFFF` / `0x00000000` | 予備はんだが切り欠きに乗っておらず、被覆越しに触っているだけ |
| 触ると値が変わる | 根元が剥がれかけ。固定剤で補強してやり直す |
| 隣接信号が連動する | 半田ブリッジ。特に 9-10-11-12 |
| 16MHz で不安定、4MHz なら安定 | 配線長・GND 戻り経路。GND を pin 8 と pin 12 の 2 本にする。<br>それでも駄目なら `boards/*.h` の `spi_fast_hz` を 8MHz / 4MHz に落とす |
| 測距距離が極端に短い | アンテナ側 3.5mm に金属／配線がある |

      pin 2 と GND が 0Ω に張り付かないこと（4.1 節）。
