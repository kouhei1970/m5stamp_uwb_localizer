# 実験計画 — 機材が届いてから測位が出るまで

**このリポジトリのコードは実機で一度も動かしていません。** 本書は、機材が届いてから
**何を・どの順で確かめ、どのフラグをいつ有効にしていくか**を決めた計画書です。

- **手順そのもの**（配線・書き込み・コマンド）は [`GETTING_STARTED.md`](GETTING_STARTED.md) にあります。本書は**順序と判断**を扱います
- **Phase 1 の受入確認の詳細**は [`GETTING_STARTED.md`](GETTING_STARTED.md)
- 原理が分からないときは [`UWB_PRIMER.md`](UWB_PRIMER.md)、略語は [`GLOSSARY.md`](GLOSSARY.md)

---

## 0. 大原則

この3つを守らないと、失敗したときに原因が特定できなくなります。

> ### 原則1: 一度に1つだけ変える
> 配線・ボード・方式・フラグを同時に2つ動かさない。**動いていた状態に必ず戻せること。**
>
> ### 原則2: 全部「既定値」から始める
> 既定は意図的に**最も保守的**にしてあります
> （`UWB_ENABLE_IRQ=n` / `UWB_TIMING_PROFILE=PollingBoth`）。
> 速度を上げるフラグは**測位が出てから**触ります。
>
> ### 原則3: 合否を数字で決めてから実験する
> 「動いた気がする」で次に進まない。各実験に**合格条件**を書いてあります。

### なぜ IRQ と遅延プリセットを最後に回すのか

この2つは**測距が成立しなくなる方向に効く**フラグです。
測位が一度も出ていない状態でこれを触ると、
「配線が悪いのか、フラグが悪いのか」が永久に切り分けられなくなります。

**まず遅い設定で最後まで通す。速くするのはその後。**

## 2. 実験 0 — 開梱時（ここで壊す事故が一番多い）

### やること
1. **半田パッドの pin 1 がどちら側かをテスターで確定する**
   → [`GETTING_STARTED.md` §3.1](GETTING_STARTED.md#orientation)
2. 電源は **公式 3.3V。チップ直結のため上限 3.6V（絶対最大 4.0V）。M5Stack の GROVE 5V も
   StampFly の GROVE（電池 ~4.35V）も直結不可、LDO 必須。`WIRING.md` §5.4**

### なぜ最初か
> **公式 PINMAP 画像を入手できておらず、パッドの向きは推定です。**
> 逆に配線すると電源逆接でモジュールが壊れます。**ここだけは実測で確定してから半田付け。**

### 合格条件
GND と 3V3 のパッドがテスターで判別でき、`docs/WIRING.md` の並びと一致した。

## 3. 実験 1 — SPI 疎通（最初の関門）

**`firmware/probe`。ここが通れば以降はソフトウェアだけの話になります。**

### フラグ
| フラグ | 値 | 備考 |
|---|---|---|
| `UWB_PROBE_BOARD_STAMPS3` / `_ATOMS3` / `_STAMPFLY` | **使うボード** | 既定は STAMPS3 |
| `UWB_BOARD_ATOMS3_PINOUT_A` / `_B` | AtomS3 のときだけ | **無印は A、AtomS3R は B** |
| その他 | **全部既定のまま** | |

### 合格条件
```
I (xxx) uwb_probe: L1 (periodic): raw DEV_ID = 0xDECA0314
```
**L1（生の SPI 読み）と L2（`dwt_probe()` 経由）の両方**が通ること。

### 落ちたときの見どころ
| 症状 | 疑うもの |
|---|---|
| `0x00000000` / `0xFFFFFFFF` | 配線（特に CS と GND）、電源が来ていない |
| たまに読める | 半田不良、SPI が速すぎる（`spi_slow_hz` は 2 MHz から動く設計） |
| L1 は通るが L2 で落ちる | リセット周り。`pin_rst` 未配線なら `hard_reset_on_begin` が効かない |

### 記録すること
**ボード / ピン割り当て / 何回目で読めたか。**
`boards/*.h` のピン番号は**すべて暫定値**なので、実配線と違ったら**ここでヘッダを直す**。

## 4. 実験 2・3 — 1対1 の測距

**`firmware/twr` を 2 台（TAG 役 / ANCHOR 役）に焼く。**

### 順序: SS-TWR → DS-TWR
まず **SS-TWR**（`UWB_TWR_METHOD_SS`、既定）。往復1回で構造が単純なので、切り分けが楽です。
通ったら **DS-TWR**（`UWB_TWR_METHOD_DS`）へ。

> **タグ役とアンカー役は必ず同じ方式にすること。** 違うと噛み合いません。

### フラグ
| フラグ | タグ役 | アンカー役 |
|---|---|---|
| `UWB_TWR_ROLE_TAG` / `_ANCHOR` | TAG | ANCHOR |
| `UWB_TWR_METHOD_SS` → `_DS` | 両方同じ | 両方同じ |
| `UWB_ENABLE_IRQ` | **n（既定のまま）** | **n（既定のまま）** |
| `UWB_TIMING_PROFILE_POLLING_BOTH` | **既定のまま** | **既定のまま** |

### 合格条件
巻尺で測った距離に対して、

- **`std_mm` が数 cm 以内**（ばらつき。これが本命）
- **`mean_mm` は数十 cm〜1 m ずれていてよい**（アンテナ遅延が未校正だから。実験 4 で消す）

> **ここで見るのは「ばらつき」であって「正確さ」ではありません。**
> 偏りはアンテナ遅延で説明がつくので、慌てて配線を疑わないこと。

### DS-TWR が SS-TWR より悪いとき
DS-TWR は**両側に遅延送信の締切**があるので、タイミング設定の影響を受けます。
`UWB_TIMING_PROFILE` が**両方 PollingBoth になっているか**を確認してください
（不一致なら起動ログに警告が出ます。§8 参照）。

## 5. 実験 4 — アンテナ遅延の校正

**症状が「ばらつきは小さいが一定量ずれている」ならこれです。**

- **1 ns のずれ = 30 cm**。無校正だと 3σ ≈ 30 cm の偏りが出ます
- 手順は [`GETTING_STARTED.md` §9](GETTING_STARTED.md#antenna-delay)
- **TWR では TX と RX の遅延の合計だけが効く**ので、内訳を気にしなくてよい

### 合格条件
巻尺の実測値と `mean_mm` が **±数 cm** で一致する。

### 記録すること
**温度**。アンテナ遅延は温度で動きます（ch9 の PLL 再校正が課題 R10 に挙がっています）。

## 6. 実験 5・6 — アンカー5台 → フル測位

### 5. アンカーを立てる（`firmware/anchor` × 5）
| フラグ | 値 |
|---|---|
| `UWB_ANCHOR_BOARD_ATOMS3` + `UWB_BOARD_ATOMS3_PINOUT_A`/`_B` | 実物に合わせる |
| `UWB_ANCHOR_METHOD_DS` | **タグと同じ方式** |
| `UWB_ANCHOR_SHORT_ADDR` | **5台とも別のアドレス** |
| `UWB_ANCHOR_CONSOLE` | y（既定）。アドレスと座標をコンソールで直せる |
| `UWB_ENABLE_IRQ` / `UWB_TIMING_PROFILE` | **既定のまま** |

### 配置（ここで精度が決まる）
> **高さをばらすこと。全部同じ高さに置くと上下の鏡像が区別できません。**
> 詳細は [`ANCHOR_PLACEMENT.md`](ANCHOR_PLACEMENT.md)。
>
> 床に並べて z≈0 になる配置では **Lv2 が毎周期 `ok:0` を返す**現象が実測で分かっています。
> その場合は `UWB_TAG_AUTO_2D_FALLBACK`（既定 y）が 2D へ落とします。
> **配置を調整している最中は、あえて n にして生の失敗を見るほうが分かりやすい。**

### 6. 測位（`firmware/tag` × 1）
| フラグ | 値 |
|---|---|
| `UWB_TAG_BOARD_*` | 実物に合わせる |
| `UWB_TAG_METHOD_DS` | **アンカーと同じ** |
| `UWB_TAG_CONSOLE` | y（既定）。**アンカー座標を焼き直さずに直せる** |
| `UWB_TAG_ENABLE_EKF` | **n（既定）**。Lv0/Lv2 が出てから |
| `UWB_ENABLE_IRQ` / `UWB_TIMING_PROFILE` | **既定のまま** |

**アンカー5台に先に電源を入れてから**タグを起動します。

### 合格条件 — ここが「フル測位」

JSON Lines の `fix` 行で、

| 見るもの | 合格 |
|---|---|
| `ok` | **`true` が連続して出る** |
| `ambiguous` | `false`（`true` なら **z を使ってはいけない**） |
| `p` | 巻尺の実測位置と一致（校正後） |
| `residual_rms` | 小さい。大きいなら**座標入力ミス**かアンテナ遅延未校正 |
| `excluded` | 特定のアンカーがいつも立つなら、その台の座標か NLOS を疑う |
| `cycle_ms` | **32 ms 前後**（＝ 31 Hz。PollingBoth の設計値） |

> **`ok` と `ambiguous` は必ず両方見ること。** `ok:true` でも `ambiguous:true` なら高さは信用できません。

**ここまで来たら目的は達成です。** 以降は速度と運用性の改善。

## 7. 実験 7 — IRQ を有効にする

**測位が安定して出るようになってから。**

### なぜ効くのか
現在はアンカーが 1 ms 周期のポーリングで受信に気づいています。
IRQ にすると気づくまでが数十 µs になり、**折返し時間が縮む**。
効果は2つあり、**速度より2つ目のほうが本質的**です。

1. 1周が 31.9 ms → 16.8 ms（31 Hz → 59 Hz）
2. **タイミング余裕が増えて成功率が上がる。SS-TWR ならクロック誤差も減る**

### 手順（**必ず2段階に分ける**）
```
段階 A: IRQ だけ有効にする（プリセットは PollingBoth のまま）
        → CONFIG_UWB_ENABLE_IRQ=y     ※ アンカー5台のみ。タグは触らない
段階 B: 起動ログで irq=active を確認する
```

### 合格条件
アンカーの起動ログが
```
irq=active (pin=2)
```
になり、**かつ測位が実験 6 と同じように出続けること**（レートはまだ 31 Hz のまま）。

| ログ | 意味 |
|---|---|
| `irq=active (pin=N)` | **成功** |
| `irq=polling (pin_irq unwired)` | `boards/*.h` で `pin_irq` が未配線。配線を確認 |
| `irq=polling (disabled by Kconfig)` | フラグが効いていない |
| `irq=polling (enable failed)` | ISR 登録に失敗。他コンポーネントとの競合を疑う |

> **IRQ の極性（アクティブ HIGH）は実機未検証です。**
> 間違っていた場合の症状は「`irq=active` なのに速くならない」。
> **待ちは 1 ms で必ず抜ける設計なので、最悪でも現状性能に落ちるだけ**で壊れません。

## 8. 実験 8 — 遅延プリセットを上げる

**ここが一番事故りやすい。**

### 【最重要】タグとアンカーで必ず一致させる
`responseTxDelayUus` はアンカーが「いつ送るか」、タグは「いつ待つか」を決めます。
**片方だけ変えると測距が成立しません。**

> **アンカー5台とタグ1台の計6台を、同じプリセットで焼き直すこと。**
> 1台でも取り残すと、その1台だけリンクが切れます。

### 手順
```
1. アンカー5台 : CONFIG_UWB_TIMING_PROFILE_ANCHOR_IRQ=y  (+ UWB_ENABLE_IRQ=y)
2. タグ1台     : CONFIG_UWB_TIMING_PROFILE_ANCHOR_IRQ=y  (UWB_ENABLE_IRQ は n のままでよい)
3. 全台を電源投入し直す
```

`AnchorIrq` は **アンカーだけ IRQ を持つ前提**のプリセットです。
タグ側は IRQ 無しのまま（StampFly 互換のため。→ [`IRQ_POLICY.md`](IRQ_POLICY.md)）。

### 不一致は自動検出されます
焼き忘れがあると、**フレームに載せた版番号と種別が食い違うので警告が出ます**:
```
W ... respondDSRange: Poll<-TAG: peer=0x0001 とタイミングプリセットの種別が違います
      (mine=AnchorIrq peer=PollingBoth)。タグとアンカーを同じプリセットで焼き直すこと
```
**この警告が出たら、測距値は信用せず焼き直してください。**

また、`AnchorIrq` を選んだのに IRQ が有効化できていない場合も起動時に警告します
（**プリセットの値は自動では変わりません**。相手と一致していることが要件なので、
片側が勝手に変えたら破綻するからです）。

### 合格条件
| 見るもの | 合格 |
|---|---|
| `cycle_ms` | **17 ms 前後**（59 Hz） |
| 不一致警告 | **出ない** |
| `ok` の連続性・`residual_rms` | 実験 6 と同等かそれ以上 |

### 悪化したら
**迷わず `PollingBoth` に全台戻す。** 戻せば実験 6 の状態に必ず帰れます
（`PollingBoth` は現在の既定値と完全に同一の数値なので）。

### `BothIrq` は当面使わない
タグ側にも IRQ が要ります。StampFly では GROVE 4本を SPI で使い切るので**取れません**。
単体の M5StampS3A なら G7 で取れますが、**タグは IRQ 非依存という方針**なので
実験的な位置づけです。
